## 1. 事实（逐条实测；命令原文见 §5）

设计文 `orchestrator/handoff/M2-01-design.md` 两处**逐字**要求使用该常量：

- `:82` —— `if_match: str | None = Header(None, alias="If-Match", min_length=3, max_length=32, pattern=IF_MATCH_PATTERN)`
- `:649-650` —— 同一签名，并注明「其中 `IF_MATCH_PATTERN: Final = r'^"[1-9][0-9]*"$'`（**逐字**抄契约 pattern，禁自己写第二份正则）」

编排器把该要求原样下发进派单文 `orchestrator/handoff/R18-lane-M2-01-S3.md`：

- `:115` —— `max_length=32, pattern=IF_MATCH_PATTERN)`，**再由 service 调 `api/common.py::check_if_match``
- `:215` —— `IDEMPOTENCY_KEY_HEADER` / `IF_MATCH_PATTERN` **不在** `__all__` 里但**确实**从 `api.common` 导入可用

**实测结果（与上述陈述互斥）**：

| 实测项 | 结果 |
|---|---|
| `grep -rn --include=*.py IF_MATCH_PATTERN src tests` | **0 命中**（唯一命中是新落地件 `api/activities.py:19` 的 docstring，其内容正是在记录本 U 项） |
| `api/common.py` 的 `__all__`（`:83` 起） | 无 `IF_MATCH_PATTERN`；且 `:22-25` 的模块 docstring 明载「**严禁在本文件重新定义上述任何符号**——那会直接复刻 R5-1 要防止的『两处各存一份』」 |
| `api/common.py:825 check_if_match(header, current_revision)` | **存在且可用**（缺头 → 428、不匹配 → 412），`:821` 的 `etag` docstring 里以**散文**形式提到正则 ``^"[1-9][0-9]*"$`` |
| `domain/ids.py` / `api/session.py` / `api/deps.py` | 均无该常量 |
| 冻结先例 `api/jobs.py:216`、`:300`（`cancel_job` 等 2 处 If-Match 形参） | 用的是**内联字面量** `pattern=r'^"[1-9][0-9]*"$'`，**不是**导入常量 |

⇒ 设计文点名的符号**从未被创建**；而唯一可用的既有先例（`api/jobs.py`，本棒同样冻结、sha `735d30baf0c4`）走的是内联字面量。

## 2. 根因

`api/common.py` 在某次搬移中被收敛为「**只保留 `import` 与 re-export**」的纯转发面（其 `:22-25` docstring 逐字如此声明，并**严禁**在本文件重新定义任何符号）。设计文 §6.2 在撰写 `update_activity` 的签名时，把「契约里存在 If-Match 的 pattern 约束」直接升格为「`api/common.py` 里存在 `IF_MATCH_PATTERN` 常量」，**既未核对该常量是否已被创建，也未注意到 common.py 的纯转发面纪律本身就会阻止在该处新建常量**。这是「设计文以想象中的符号面代替实测符号面」的典型形态，与 D-050（设计文的具名测试清单未与已落覆盖面做对撞）同源：**设计文由 max 档产出，但其中的枚举／符号类陈述若不经实测对撞，就会失真**。

## 3. 影响

- **交付面**：零返工。lane S3 依 §9 停手报 U（未自行改冻结件、未发明常量），编排器按 **A247** 裁定采纳「照 `api/jobs.py` 冻结先例用内联字面量」，`api/activities.py` 以该形态落地并通过全部判据（V1–V11 编排器独立复验全绿）。
- **技术债（如实登记，不粉饰）**：正则字面量 `r'^"[1-9][0-9]*"$'` 目前在 `src/**` 出现 **3 处**（`api/jobs.py:216`、`api/jobs.py:300`、`api/activities.py`），**与设计文「禁自己写第二份正则」的意图相违**。该相违**不是 lane 的裁量失误**，而是设计文指定了一个不存在的单源点、而唯一可落地的单源点（`api/common.py`）对本棒冻结所致。三处的**值逐字相同且都等于契约 pattern**，故当前不存在语义分叉风险，但缺少机器化钉住。
- **后续放大风险**：`api/common.py:829` 的 docstring 明载 `check_if_match` 「供 M1 起 **16 个** If-Match op 复用」。若不在 M1 开闸前建立单源常量，该字面量将复制到十余处。

## 4. 处置（A247 同批闭合；技术债转 FU-59）

1. **A247 裁定采纳候选 ①**：本棒维持 `api/jobs.py` 的内联字面量形态。理由：(a) 零设计裁量——字面量的**值**与**形参形态**（`alias="If-Match", default=None, min_length=3, max_length=32, pattern=...`）是逐字照抄既有冻结先例，不是新裁；(b) 值的单源仍是**契约**（design §6.2 明载 pattern 逐字抄契约），未产生第二真源；(c) 候选 ② 需改冻结件 `api/common.py`，超出 M2-01/S3 写权，强行落地即越权。
2. **候选 ② 转为 FU-59（P2，M1 开闸前）**：由持 `api/common.py` 写权的一棒新增 `IF_MATCH_PATTERN: Final = r'^"[1-9][0-9]*"$'`（同批更新 `__all__`，并注意 `:22-25` 的「纯转发面」纪律——需先裁定该常量应定义在 `domain/` 还是 `api/common.py`，避免复刻 R5-1 的「两处各存一份」），随后把 `api/jobs.py` 2 处 ＋ `api/activities.py` 1 处改为 import，并补一条哨兵钉住「全仓该字面量**只出现 1 次**」。
3. **派单文缺陷归编排器自纠 R18-4**：派单文 `:215` 断言「`IF_MATCH_PATTERN` 不在 `__all__` 里但**确实**从 `api.common` 导入可用」——这是编排器**照抄设计文而未做 AST 实测**的陈述，属 PRE-20（枚举／符号类断言必须派单前实测）的违例。防再发：把「派单文里点名的每个符号都必须 AST／import 实测存在，否则必须显式标注『待创建 ＋ 谁创建』」并入 FU-58 的机器化派单前自检。
