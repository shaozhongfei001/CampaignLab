## 2 实测（编排器独立取证）

`spec/CampaignLab-SDD-v1.0/fixtures/api-examples.json` = 15919 B，顶层键 `usage` / `examples` /
`estimate_response`；`examples` 为 **22** 条、以 operationId 为键：

```
createWorkspace createActivity updateActivity createRule configureImport runComparison
runReview runDiagnosis interpretQuestion executeQuestion computeEstimate createCase
createRun createCandidate createPreflight recordReceipt createReport signReport
correctSnapshot createAction reviewAction createExport
```

**其中无任何 jobs 端点**。关键词命中数实测：`Job`=0、`lease_until`=0、`retry_of`=0、
`QUEUED`=0、`attempt`=0、`result_ref`=0。`fixtures/README.md` 对该文件的原文说明也是
「核心接口**请求体**与预期指针。资源 ID 在测试用例解析为实际 ID」——即它本就不提供响应 DTO 样本。

活契约侧的权威事实（`contracts/openapi.json`，130 个 `components.schemas`）：
jobs 共 4 个 op，`listJobs` -> 200 `JobPage`、`getJob` -> 200 `Job`、`cancelJob` -> 200 `Job`、
`retryJob` -> **202** `Job`；`Job` schema 存在。故 `Job` 字段口径的唯一权威来源是活契约，
经 D-020 修复后已完整展开进 `orchestrator/handoff/M0-04.slice.json` 的 `operations.*.schemas.Job`。

## 3 同型风险排查（扩大取证结果）

四张新卡的 `fixtures` 行写「`api-examples.json`（15919 B，可整读：DTO 样本）」，其 S7 子任务写
「按 `api-examples.json` 样本逐字段铺开」，而 S7 点名的多是**响应** DTO。逐一核对：

| 卡 | S7 点名的 DTO | 是否存在于 130 个 schema | 该卡 op 是否在 22 条样例中 |
|---|---|---|---|
| M3-01 | `Review` / `ReviewCreate` / `MetricComparison` | 全部存在 | `runReview` 在（examples[6]），仅**请求体** |
| M3-02 | `Estimate` / 试算 DTO | `Estimate`、`EstimateCreate` 存在 | `computeEstimate` 在（examples[10]）+ 顶层另有 `estimate_response` |
| M3-03 | `QuestionPlan` / `QuestionResult` / `QuestionInterpretation` | 全部存在 | `executeQuestion`(examples[9])、`interpretQuestion`(examples[8])，仅**请求体** |
| M4-01 | `Report` / `SignReport` / `ReportSummaryPage` | 全部存在 | `createReport`(examples[16])、`signReport`(examples[17])，仅**请求体** |

**结论**：schema 名**没有杜撰**（这是与 M0-04 的关键差别），但「按 `api-examples.json` 逐字段铺开
响应 DTO」的指引不成立——该文件只给请求体。响应 DTO 的权威来源是切片内已完整展开的
`operations.*.schemas`。四卡均为 flash 档 S7，若不澄清，flash lane 极可能凭记忆补字段。

> **编排器自我更正（留痕，不改写历史）**：本单初稿曾断言「卡内点名的 `ReviewCreate` /
> `MetricComparison` / `Threshold` / `QuestionPlan` / `QuestionResult` / `QuestionInterpretation` /
> `SignReport` / `ReportSummaryPage` / `RuleVersion` 在 130 个 schema 中根本不存在」。
> 复核后该断言**错误**：以上名称全部存在；130 个 schema 中不存在的只有裸名 `Threshold` 与
> `Question`，而任何卡都未如此引用（已用 grep 反引号形态实测，零命中）。
> 严重度因此由 MAJOR 下调为 MINOR，处置由「重写卡内 schema 名」收窄为「加注澄清样本来源」。
