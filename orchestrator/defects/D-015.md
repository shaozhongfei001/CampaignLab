# D-015 · 缺陷单落盘与 state.json 台账写入非原子，产生可复现的假 RED

- 严重度：**MINOR**（流程；会污染并发 lane 的门禁结论）
- 状态：FIXED_PENDING_Q
- 发现时间：2026-11-13T01:54:49+08:00（Q 判定档 BLK-Q5 → 已自愈，转记 Q-N5）
- 发现者：Plato 与编排器**各自独立**撞到同一次假 RED
- 证据：`b1f38a9` 时点编排器实测 `1 failed / 37 passed`（`orphan=['D-010']`）；
  Plato 于 01:36:17 实测同样 rc=1，01:39:43 复测 rc=0、38 passed、台账 10 条

## 1. 现象

`tests/unit/test_state_ledger.py::test_every_md_on_disk_has_ledger_entry` 要求
「磁盘上每个 `D-*.md` 都必须在台账里有对应条目」。当编排器**先写 `D-010.md`、后写台账**时，
两步之间的窗口里任何 `pytest` 都会判红。本轮编排器首版脚本正是把「台账 upsert」排在门禁复验之后，
被自己的守卫拦下（**守卫按设计生效，不是误报**）；同一窗口 Plato 也测到一次假 RED。

## 2. 修复

1. 顺序固化为：**台账 upsert → 写 state.json → 跑 `test_state_ledger.py` 确认绿 → git add → 算分母 → 全门禁 → 提交**。
2. 缺陷单 `.md` 与台账条目必须在**同一次提交**内落地（禁止跨提交）。
3. 台账 upsert 时顺带规范化：条目缺 `file` 键即按 `orchestrator/defects/<id>.md` 补齐
   （本轮实测 D-006/D-007/D-008/D-009 四条缺该键，已补齐，消除悬空引用面）。
4. 手册新增 **15.9** 明列该顺序为硬性纪律。

## 3. 教训

双向一致性守卫必然在「两步写入」之间产生窗口。无人值守长程里，任何跨步骤的一致性都必须
用**单次原子提交**收口；并发 lane 存在时，窗口内的红不是噪声而是真实信号，必须靠顺序而非重试消除。
