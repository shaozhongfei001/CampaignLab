- **修复时间**：2026-11-13T08:45:01+08:00
- **严重度**：中（不阻断交付，但使 lane 无法按派单文原文取 AC，被迫回落到 `pages.UI-01.meta.acceptance` 二手来源）
- **影响范围**：`orchestrator/handoff/M0-03.slice.json`

## 1. 现象

M0-03 派单文要求 lane「按切片的 `acceptance_rows` 抽取 AC-001 原文」，但 F lane 实测该切片顶层
keys 只有 `spec_version / source / operations / pages / truncated_schemas`，**无 `acceptance_rows`**。
lane 未自行发明 AC 原文，改为依 `pages.UI-01.meta.acceptance` 取用并如实回报（R4-Q4），处置正确。

## 2. 根因

编排器生成该切片时未传 `--ac` 参数。`scripts/contract_slice.py` 只在显式给 `--ac` 时才写
`acceptance_rows` 键 —— 与 D-021 修复后的「全命中时不写 `missing` 键」属同一类
**以键存在性表达语义**的设计；但派单文把它当成必然存在的键来引用，属编排器侧的接口误用。

## 3. 处置（本轮已执行，全部为编排器实测）

以 `--ac AC-001,AC-034` 重切 `M0-03.slice.json`：

| 项 | 旧值（重切前） | 新值（本次实测） |
|---|---|---|
| sha256[:16] | `d0ebef26764e7f1c` | `b19d38b8ce25fbd1` |
| bytes | 17203 | 17683 |
| 顶层 keys | 无 `acceptance_rows` | 含 `acceptance_rows`（AC-001、AC-034） |

`acceptance_rows` 形态为 `{AC-id: [编号, 要求原文, 判据原文, 取证方式]}` 字典，
AC-001 与 AC-034 各 4 列，逐字取自 `spec/CampaignLab-SDD-v1.0/ACCEPTANCE.md`，未改写。

**纯增量断言（本次实测，非采信自报）**：以 `git show HEAD:` 取重切前版本逐键比对，
`added_keys = ['acceptance_rows']`、`removed_keys = []`，其余五个既有键
（`operations` / `pages` / `source` / `spec_version` / `truncated_schemas`）的规范化 JSON
序列化 `identical=True`（逐项比对输出见提交说明所附实测）。故本次重切不改变任何 lane
已据以交付的 ops/pages 事实，F lane 的 S6–S9 产物无需返工。

旧切片备份 `/tmp/M0-03.slice.json.bak`：实测存在（17203 B）。
无论如何，重切前版本的**权威可复核来源是 git 历史**（`git show 71f9644^:orchestrator/handoff/M0-03.slice.json`
之前的任一入库版本），不依赖 WSL `/tmp`。

## 4. 防复发

1. 派单文引用切片键前，必须先打印该切片顶层 keys 的实测清单，禁凭记忆写键名。
2. `acceptance_rows` 与 `missing` 一律按「键存在性」判读：
   - 需要 AC 原文 → 生成切片时**必须**显式传 `--ac`；
   - PRE-3 新鲜度断言 → `('missing' not in slice) and slice['truncated_schemas'] == []`（见 A18）。
3. 已并入 `state.json -> resume.dispatch_requirements` 的 PRE-3 断言口径条目。
