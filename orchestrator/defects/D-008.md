## 1. 缺陷 1：AC-034 / AC-035 转述错误

`orchestrator/tasks/M0-02.md` 修复前的 gates：

| AC | 任务卡（错） | spec `qa/ACCEPTANCE.md` 与切片 `acceptance_rows`（权威） |
|---|---|---|
| AC-034 | 「深链与刷新可回到合法入口（服务端侧前置：资源 ID 校验与 404/越权按不可见处理）」 | 「测试过期会话、错误 Host/Origin、跨工作区 ID 和上传失败」→「按 401/403/404/413 或 422 返回。隔离、路径、日志和 ETag 证据可查」（HTTP 负例） |
| AC-035 | 「并发与重启语义（会话过期、进程重启后会话失效）」 | 「按 M0 锁版本、迁移、核对包和 API」→「verify_package.py、DDL 等价、OpenAPI 请求响应及前端生成类型通过。锁和运行环境清楚」 |

- 「深链与刷新回到合法入口」实际属 **UI-01 页面侧 = M0-03**；
  「会话过期／重启失效」在权威口径里归 **AC-001 + AC-034**，不是 AC-035。
- 危害：S5 会按错误口径写 `ac.md` 并判 PASS，Q 若只对照任务卡也会跟着判绿。

## 2. 缺陷 2：`scope_allow` 缺三项，与卡内其它段落自相矛盾

| 缺失项 | 为什么必须允许 | 权威依据 |
|---|---|---|
| `pyproject.toml`（连带 `uv.lock`） | M0-01 设了 `[tool.uv] package = false`，实测 `uv run --no-sync python -c "import campaignlab"` -> `ModuleNotFoundError`；gate「`uv run python -m campaignlab doctor` 可运行」与「pytest 全绿」都无法达成 | **`pyproject.toml:13` 注释原文**：「M0-02 交付 CLI 与 `__main__` 后删除 `package = false`，即恢复为可安装项目（届时 uv 需要把构建后端 hatchling 纳入锁文件）」→ 这本就是 M0-02 的既定交付，不属范围扩张 |
| `evidence/M0/M0-02/**`、`evidence/M0/summaries/M0-02.md` | 卡内 `outputs:` 明确要求写这些证据，但 `scope_allow` 未含 → 子智能体照 scope 执行会**无法交付 outputs**，照 outputs 执行则**越界**（手册 6.4 要求越界即回报，形成死锁） | 任务卡自身 `outputs:` 行 |
| `src/campaignlab/application/`、`infra/db/`（卡内 S3 产出列只写 `api/**`） | `state.json` 的 `tasks.M0-02.scope` 已含这两项，卡内档位表的 S3 产出列漏写 → 两处口径不一致 | `orchestrator/state.json` |

## 3. 修复

1. 任务卡 AC-034 / AC-035 两行按 spec 原文重写，并标注「已按 spec 原文修正，见文末裁定 Q1」。
2. 「契约测试」gate 口径按裁定 Q2/Q3 收窄：Problem 结构、幂等重放、`createWorkspace` 的 ETag 发布
   在 HTTP 层取证；作业 202/GET 语义与 If-Match 412/428 在 DTO/单测层覆盖，HTTP 端到端
   `deferred_to` 拥有对应 op 的后续任务（全契约 11 个 202 op、16 个 If-Match op 均不在 M0-02 的 5 个 operationId 内，已实测）。
3. `scope_allow` 补 `pyproject.toml`、`uv.lock`、`evidence/M0/M0-02/**`、`evidence/M0/summaries/M0-02.md`；
   `state.json` 的 `tasks.M0-02.scope` 同步。
4. M0-03 任务卡加注：「深链与刷新回到合法入口」归 M0-03（UI-01）。
5. 派生 ADR-005（Problem.type 与运行参数默认值）与 CR-002（`listWorkspaces.status` 契约不一致）。
