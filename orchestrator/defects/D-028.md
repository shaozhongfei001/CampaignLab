## 2. 缺陷定性

本项目反复钉住「单一来源」：ADR-005 §2.1 的 Problem/ETag 单点、M0-02/S3a 的 `infra/db/paths.py` 数据库路径单一来源、
D-004 的「工具读取路径与版本戳来源必须随契约升级同步检查」。两处同判据实现属**可复现的技术债**：
任一侧改了 ini 路径、改用 `get_current_head()` 之外的判据（如读 `alembic_version` 表）、或加了异常兜底，
另一侧会**静默分叉**，结果是 `doctor` 报的迁移状态与 `/api/v1/health` 的 `schema_revision` 给出不同答案——
而 `schema_revision` 是契约可见面（A71），分叉会直接污染 AC-034/AC-035 的取证。

## 4. 处置方案（Round 7/8 派独立 flash 小片，预算 <=8k）

1. 新增 `src/campaignlab/infra/db/migration_head.py::read_migration_head()` 作为**唯一**实现（落 `infra/db/` 而非 `application/`，
   因为它是迁移基建、且 `cli` 与 `application` 两侧都要依赖它，放 application 会造成 cli -> application 的反向依赖）；
2. `cli._migration_head()` 与 `health_service.read_migration_head()` 双双改为**委托**，删除各自的重复实现；
3. 新增守护断言：`get_current_head` 在 `src/` 下的**定义点唯一**（1 处真实调用 + N 处委托），grep 计数入守护；
4. 门禁：pytest / mypy / ruff check / ruff format --check / doctor 全表 rc 与输出双判（D-027 口径），
   `doctor` 的 PASS/WARN/FAIL 计数与迁移判据行为**零变化**（纯重构，由既有用例守护）。
