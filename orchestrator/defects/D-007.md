# D-007 · `doctor.sh` 字体检查在 pipefail 下因 SIGPIPE 恒判假 WARN（非确定性门禁）

- 严重度：**MAJOR**（G14 是 16 项自检门禁之一；非确定性门禁在无人值守长程里比稳定红更危险——它随机产生假绿与假红）
- 状态：FIXED_PENDING_Q
- 发现者：Q lane 取证员（qwen3.8-flash，Q-VERIFY-M0-01/collect，发现编号 F-A4-1）
- 复现与修复者：编排器本体
- 发现时间：2026-11-12T23:30:05+08:00
- 证据：`evidence/M0/Q-VERIFY-M0-01/collect/04-defects.md`、`evidence/monthly/M0-P01/run-04/commands.md` 第 8 节
- 回归测试：`tests/unit/test_doctor_determinism.py`（4 条）

## 1. 现象

`fonts-noto-cjk 1:20230817+repack1-3` 已正确安装（`dpkg -l` 有 `ii`，`fc-list` 命中 10 条
`Noto Sans CJK`），但 `bash scripts/doctor.sh` **多数情况下**输出：

```
[WARN] 未安装 Noto Sans CJK（BLK-02 未解除，字体度量可能与行内设计基线不一致）
```

同一脚本、同一环境，摘要在 `PASS=16 WARN=0` 与 `PASS=15 WARN=2` 之间随机跳变。

## 2. 根因

`scripts/doctor.sh:246`（修复前）：

```bash
if fc-list 2>/dev/null | grep -qi "noto sans cjk"; then info ...; else warn ...; fi
```

脚本头部为 `set -uo pipefail`。`grep -q` 一旦命中就**立即退出**（本例命中在第 21 行 / 共 169 行），
而 `fc-list` 输出约 18,876 字节、超过管道缓冲区，仍在继续写 → 收到 **SIGPIPE**，退出码 141；
`pipefail` 把 141 作为整条管道的退出码 → `if` 判定为假 → 走 `else` 报「未安装」。
是否触发取决于 `fc-list` 与 `grep` 的调度竞态，故为**非确定性**。

## 3. 定量复现（修复前，30 次）

| 退出码 | 次数 | 含义 |
|---|---|---|
| 0 | 2 | 侥幸绿（fc-list 恰好在 grep 退出前写完） |
| 141 | 28 | SIGPIPE → 假 WARN |
| 1 | 0 | 真的未命中 |

假 WARN 率 **28/30 ≈ 93%**。对照组 `fc-list :lang=zh | grep -qi noto` 跑 20 次全 rc=0，
因为 `:lang=zh` 输出仅 3,269 字节 < 管道缓冲，`fc-list` 不会阻塞 → 不触发 SIGPIPE。
**这解释了 Q 取证员与编排器结论不一致的原因**：编排器此前那次（22:55）落在 7% 的侥幸绿上，
并据此在提交 `8ce2bdc` / `33bf5c5` 里写了「WARN=0」——该表述不成立，已在 run-04 第 8 节更正留痕。

## 4. 修复

```bash
NOTO_CNT="$(fc-list 2>/dev/null | grep -ci "noto sans cjk")"
if [ "${NOTO_CNT:-0}" -gt 0 ]; then info "Noto Sans CJK 已安装（fc-list 命中 ${NOTO_CNT} 条）"; else warn "..."; fi
```

`grep -c` 必须读完全部输入才输出计数，不会提前退出 → 无 SIGPIPE；顺带把命中条数写进消息，便于取证。

## 6. 回归测试钉住的不变量

`tests/unit/test_doctor_determinism.py`：

1. `test_no_sigpipe_prone_grep_q_in_scripts`：静态扫描 `scripts/**/*.sh`，出现「管道接 `grep -q`」即失败
   （篡改负例的静态等价物；同时含**分母断言**——扫到 0 个 .sh 直接 `pytest.fail`，禁止静默通过）。
2. `test_doctor_font_check_uses_count_not_quit`：必须含 `grep -ci "noto sans cjk"`，且不得回退为 `grep -qi`。
3. `test_doctor_summary_is_deterministic_across_three_runs`：doctor 连跑 3 次，`PASS/WARN/FAIL` 摘要必须逐字相同、rc 恒为 0。
4. `test_noto_detection_is_stable_over_20_samples`：20 次采样命中条数必须唯一（直接复现原抖动）。

## 7. 连带结论（重要判读纪律）

- `doctor.sh:54-59` 会用 `git status --porcelain` 检查脏树并 **WARN**。因此
  **「子智能体正在写文件」时跑 doctor 必然多出 1 条 WARN**，这不是缺陷。
  判定 G14 时必须先看 WARN 的**文本**，不能只看 WARN 计数；脏树 WARN 与 SKIP_VERIFY WARN 属预期。
- BLK-02 的关闭结论**不受影响**：字体确实已装（`dpkg` + `fc-list` 命中 10 条为独立证据），
  此前的 WARN 是工具缺陷造成的假阴性，不是环境缺失。
