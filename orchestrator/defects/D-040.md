## 1. 现象与实测

`~/.local/share/campaignlab/state/campaignlab.db` mtime 2026-11-14 02:32:51、0 字节；gate1 在 gate4 前后的 WARN 文案实测发生变化（raw/q-cmdlog.jsonl tags G1/G2）。Q lane 未删该产物（删除也是变更，不归它裁）—— 处置正确。

## 2. 根因

「只读」被当成命令的**标签**而非需要实证的**性质**。alembic 的 current 子命令必须建立数据库连接才能读 alembic_version，而 SQLite 的连接语义即「文件不存在则创建」。

## 3. 责任归属

双侧。产品侧：`alembic current` 经由 `migrations/env.py` 建 engine 并 connect，SQLite 在 connect 时即创建 db 文件（SQLite 既定行为），故副作用来自「连接」而非「查询」本身 —— 一个对外表现为只读的命令不应产生持久写效果。编排器侧：写派单文时把 `alembic current` **假定**为只读并排在 doctor 之前，未实测其只读性，正是这个未验证的假定造成顺序依赖。

## 4. 阻塞性判定

不阻塞：副作用落在**仓库外**（`~/.local/share/campaignlab`），对 A144 三段式、提交树与产品行为均无影响。且 D-039 修复后（gate 命令统一注入 scratch `CAMPAIGNLAB_DATA_DIR`）该副作用会落到临时目录、不再污染宿主默认位置 —— 即主要触发路径被 D-039 覆盖，故 severity 由 lane 建议的 Medium 下调为 MINOR。仍独立立单，因为「只读命令有写副作用」这一性质在 M5-01/M5-02 取证与 `verify_artifact_index` 类只读校验里会再次咬人。

## 5. 修复范围

① `migrations/env.py` 或 gate 命令层：使只读状态查询不落盘（或统一注入 scratch data dir，随 D-039 一并落地）；② 编排器侧立规 `rule_readonly_gate_must_be_idempotent`；③ gate 排序要求：有副作用的 gate 排在其观测面相关 gate 之后，或在派单文标注顺序依赖。**本轮不实施代码修复**，避免动 M0-02 已翻 DONE 的交付面。
