# D-018 · 任务卡「叙述正文行数」口径不可复跑，且尾部无上限可绕过该口径

- 严重度：**MINOR**（治理面度量可信度；不影响已交付代码，但使手册 3.1 的上限不可执行）
- 状态：FIXED_PENDING_Q
- 发现时间：2026-11-13T04:05:00+08:00（D-016 补卡批次 1 复核时，编排器与子智能体 Dirac 各自独立发现）
- 发现者：编排器 + Dirac（T lane，qwen3.8-flash，N5 主动上报）
- 证据：`docs/delivery/LONG-HORIZON-ORCHESTRATION.md` v1.6 §3.1 与 §6.4、
  `tests/unit/test_task_card_narrative.py`（本次上线）、编排器对 12 张卡的结构实测

## 1. 事实（三个形态）

**形态一：自述数字无法复跑。** 手册 v1.6 §3.1 原文写
「**叙述正文 ≤ 60 行**……（实测 M0-02 55 行 / M0-03 63 行）」。
按 v1.7 固化的口径（卡首 → 「子任务档位表」表头行之前）实测：

| 卡 | 整卡行数 | head（表头前） | 档位表 | tail（表后） |
|---|---|---|---|---|
| M0-02 | 99 | **29** | 7 | 63 |
| M0-03 | 156 | **29** | 12 | 115 |

自述的 55 / 63 与 head（29 / 29）、整卡（99 / 156）均对不上，属**未写明口径的第三种数法**，
任何人无法复现 —— 与 D-006（分母不可复现）、D-012（写死计数）同类。

**形态二：尾部无上限，head 上限可被绕过。** 固化 head 口径后，U 项（未决问题）与裁定追注
都落在档位表**之后**，不受 60 行约束。Dirac 在 N5 主动上报：按旧口径其 8 卡为 46–56 行，
按新口径为 34–43 行，两者都合规，但「新口径下 U 项不再受限」意味着可以无限追加 U 项
把一张卡写成任意长而始终「合规」。实测非历史卡 tail 为 19–25 行，历史卡 M0-02/M0-03
tail 为 63/115 行（其中 15/18 行是历史裁定追注 blockquote，按项目纪律不得删改）。

**形态三：§6.4 示例违反 §15.5 硬约束。** §15.5 规定档位表必须是
`| 子任务 | 档位 | 预估 token | 产出 |` **四列**且「无拆解表不得 spawn」；
而 §6.4 的三个示例表（M0-02 / M1-01 / M2-02）只有「子任务 / 档 / 产出」**三列**，
缺「预估 token」。示例是派单时最常被照抄的部分，缺列会直接导致 §6.6 的
token 上限（flash 60k / max 200k）无从预估 —— 本轮 Dirac 批次 1 自报 119k
越限近一倍，与此有因果关系。

## 2. 影响

- 手册 3.1 的行数上限在 v1.6 下**不可执行**（无口径 → 无法判定违规）。
- 卡片长度可被合法绕过，长程无人值守下会持续膨胀，推高每次派单的上下文成本。
- §6.4 示例缺 token 列 → 派单者照抄后无法做成本预估，§6.6 配额条款失效。

## 3. 修复方案（本次提交）

1. 手册升 **v1.7**：
   - §3.1 固化口径为「**卡首 → 档位表表头行之前**」，并**删除**不可复跑的 55/63 自述，
     改为指向本守护测试（禁写死，依 D-012/D-014）；
   - §3.1 同时新增 **tail ≤ 40 行**与**整卡 ≤ 200 行**两条上限，封堵形态二；
   - §6.4 三个示例表补齐「预估 token」列，并注明「档位表是派单唯一依据、
     `tier_planned` 仅为默认档」（与 §15.5 一致）。
2. 上线机器守护 `tests/unit/test_task_card_narrative.py`（7 例）：
   head ≤ 60、tail ≤ 40、total ≤ 200、表头四列逐字相等、无表卡须在 LEGACY_NO_TABLE
   且单调收敛、LEGACY_TAIL_ANNOTATED 只豁免 tail 而 head/total/表头仍须达标、
   卡数分母下限（防 glob 扫空假绿）。
   已做**两条篡改负例**自证会红：删「预估 token」列 → 表头断言 FAILED；
   尾部灌 60 行 U 项 → tail 断言 FAILED；还原后卡文件 git diff --quiet 为 IDENTICAL。
3. LEGACY_TAIL_ANNOTATED 设为 M0-02 与 M0-03 两张：其 tail 是历史裁定追注，
   按「历史测量值绝不重写，只加注」的项目纪律**不得删改**，故只豁免 tail；
   两卡 head 均为 29 行、整卡 99/156 行，其余三项实测达标。

## 4. 教训

任何写进手册的**度量**都必须同时给出：① 可复跑口径（起止边界、计数单位）；
② 机器守护（测试）；③ 权威存放位置（state.json 键）。
只写数字不写口径 = 不可证伪的自述，与 D-006/D-012 同根。
另：手册内的**示例**具有规范效力（会被照抄），示例必须与硬约束条款同构，
否则应以硬约束条款为准并修正示例。
