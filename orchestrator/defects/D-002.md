# D-002 前端设计基线此前无机读校验，CI 无法守护其字节完整性

- 严重级：MINOR（不影响已交付功能，但属治理缺口；三份基线中唯一未被 CI 覆盖的一份）
- 发现者：Lane T（编排器），在 M0-P01 为补丁基线接 CI 时对照发现
- 受影响对象：`spec/frontend-template-spdb-v1.1/`（45 个文件，ADR-003 的前端设计基线）
- 现象：
  - `spec/CampaignLab-SDD-v1.0/SHA256SUMS` 与补丁 `DELTA-SHA256SUMS` 都是机读清单，可 `sha256sum -c`；
  - 前端模板基线目录内**没有**任何清单文件；其 8 项产物哈希只写在自带 `README_设计与使用说明.md` 第九节表格里；
  - `scripts/` 下没有任何脚本校验它，`grep -n "frontend-template" scripts/*` 无命中；
  - 因此 ADR-003 声称的「8 个产物 SHA256 前 16 位逐项一致」只在入库当时人工核对过一次，之后无法自动复验。
- 附带发现（同类陷阱）：CI 里若写 `sha256sum -c spec/CampaignLab-SDD-v1.0/SHA256SUMS`（在仓库根执行）
  会因清单内路径是**目录内相对路径**而全部 FAILED；而 `... | head -3` 会把 rc 掩盖成 0。
  本次已改为 `cd` 进目录后校验，并且不再用管道掩盖 rc（与手册第 13.2/13.3 节一致）。
- 修复：
  1) 新增 `scripts/check_frontend_baseline.py`（stdlib，只读）：解析 README 第九节表格，
     逐项比对 SHA256 前 16 位**与字节数**；表格式变化（解析到的行数 ≠ 8）直接 rc=2 而不是静默通过；
     README 自身与 `00_模版入口.html` 按原文说明不参与（文件无法记录自己的哈希）。
  2) 接入 CI `contract-gate` job：三份基线各一个 step（v1.0 清单 / v1.0.1 补丁清单 / 前端模板）。
- 验证（实测 rc）：
  - `python3 scripts/check_frontend_baseline.py` → 8/8 OK，rc=0
  - 篡改负例：向 `css/tokens.css` 追加一个换行 → rc=1（FAIL），`cp` 还原后 rc=0，`git status spec/` 干净
  - `ruff check .`=0、`ruff format --check .`=0、`mypy`=0（5 个源文件）、`pytest -q`=0（8 passed）
  - `bash scripts/verify.sh`=0、`qa/verify_package.py`=PACKAGE PASS 6/6、`check_contracts.py check`=PASS
- 状态：FIXED（证据 `evidence/monthly/M0-P01/run-02/frontend-baseline.log`）。
  待 M0 阶段 Q 交叉验证时复核本单与 D-001。
