## 1. 现象与实测

守护 `tests/unit/test_clock.py::test_datetime_now_only_appears_in_clock_module` 的实现是**逐行源文本正则**：

```python
SRC = Path(__file__).resolve().parents[2] / "src" / "campaignlab"
NOW_CALL = re.compile(r"datetime\.now\(|\.utcnow\(|time\.time\(")
for path in sorted(SRC.rglob("*.py")):
    if path.name == "clock.py":
        continue
    for lineno, line in enumerate(path.read_text(...).splitlines(), 1):
        if NOW_CALL.search(line):
            offenders.append(...)
```

它**不解析 AST、不区分代码与注释/docstring** —— 只要 `src/` 下任何一行文本里出现那三个模式之一就判红。
lane Y2 在 `worker/service.py` 的模块 docstring 第 35 行**说明自己遵守显式时钟**时，把该字面量写进了散文里，
于是被自己描述的守护判红。更讽刺的是同一行还写着「守护按 **AST** 判红」—— 对守护机制的判断也是错的。

该缺陷在 lane 侧**未被发现**，因为派单文 §四 明禁 lane 跑全表 pytest（全表归编排器在冻结索引树上复跑），
而 lane 自跑的「10 个 unit 文件 + integration/jobs」路径限定集合里**不含 `test_clock.py`**。
lane 的 11 条阳性对照里 PC6 是「往 service.py 注入 `_PROBE = datetime.now()` → 红 1」，
说明它**知道**这条守护存在并有牙，却没有意识到自己的 docstring 已经踩中同一个模式。

## 2. 根因

**同一类假红的第三次重现（R13-2 家族）**：用「全文搜字面量」的守护去钉一条语义不变量，
就必然会把「谈论该字面量的散文」误判为违规。

- R13-2：lane 对全文搜 `type: ignore`，命中 `worker/deps.py` docstring 里的**声明文本**而假红；
- 本轮 lane 自己在回执 §⑦ 里也复述过这个教训，并说明「改为 AST 定位行号」；
- 但 `test_clock.py` 这条守护**本身**仍是源文本正则，于是 lane 改对了探针、却在交付物的散文里踩了同一个坑。

**双向根因**：① lane 侧 —— 自验集合未覆盖全表，且写 docstring 时未反查「我要写的字面量是否被某条守护当模式搜」；
② 工装侧 —— `test_clock.py` 的守护口径过宽（应按 AST 判「调用表达式」，而非按文本判「出现即违规」），
把散文与代码混为一谈，属于**守护自身的假阳性面**。

## 3. 责任归属

lane Y2（交付质量：docstring 触发既有守护）；编排器（治理面：`test_clock.py` 的守护口径自 S3c 起就过宽，
历经多轮全表门禁未被识别为假阳性源；且派单文禁止 lane 跑全表，客观上使 lane 无法自证这一类红）。

## 4. 阻塞性判定

**不阻塞交付语义**：`worker/service.py` 的运行期行为完全正确 —— AST 实测该文件**零** `datetime.now` 调用、
零 `time` 导入，`cancel_job` / `retry_job` 的 `now` 均为必填关键字参数（显式时钟达标，红线 3 未被违反）。
红的只是「散文里出现了被守护当模式搜的字面量」。

**但必须修**：它让全表 pytest 判红 ⇒ 冻结树门禁无法通过 ⇒ 整个 S2c 无法入库；
且若不修而选择放宽守护，就会真的打开「偷取系统时间」的口子。

② `test_clock.py` 的守护口径升级为 AST（归 **FU-49**，非关键路径窗口，与 FU-39 的工装批次同批）。

## 6. 修复方案

**①（本提交已做）**：把该行改写为不含被搜字面量的等价表述，并**就地留下陷阱说明**，避免下一棒重踩：

> ``datetime`` 模块的 now 工厂之类取系统当前时间的调用。
> ⚠ 该守护（``tests/unit/test_clock.py``）是**按源文本正则**逐行扫描 ``src/`` 的，不是 AST ——
> 故连**本 docstring 里出现那个字面量都会判红**（D-045 实测踩过）。此处刻意以描述代替字面量。

修正后实测：`service.py` 12685 → **12924 B**、254 → **256 行**、sha256[:12] `ad62252fd1de` → **`7b0dd1591fd5`**；
