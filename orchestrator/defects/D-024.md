# D-024 · M0-03-design.md §11.3 G6 端口守卫为**假绿**（cwd 敏感 + 判据过宽）

- **状态**：OPEN → 处置口径本轮已定并生效，随提交 B 入库（历史行只加注不改写）
- **发现时间**：2026-11-13T08:45:01+08:00（Round 5 · 编排器独立复验 F lane 时实测）
- **严重度**：中偏高（**假绿**：一条 rc 被记为「无匹配」的期望值，实际是命令根本没跑起来）
- **影响范围**：`orchestrator/handoff/M0-03-design.md` §11.3 G6 行；端口纪律 NOTE-01 的自证链

## 1. 现象（三条实测，均在 WSL 侧执行）

| # | cwd | 命令 | 实测 rc | 输出 |
|---|---|---|---|---|
| 1 | `web/` | `grep -rn '300[012]' web/*.config.*` | **2** | `grep: web/*.config.*: No such file or directory` |
| 2 | 仓库根 | `grep -rn '300[012]' web/*.config.*` | **0** | 命中 1 条：`web/vite.config.ts:32` |
| 3 | 仓库根 | `grep -rnE '^[[:space:]]*(port\|target)[[:space:]]*:.*300[012]' web/*.config.*` | **1** | 无匹配 |

而 `M0-03-design.md:336`（§11.3，表头明写「门禁实测（**web/ 下**）」）把 G6 记为 `rc=1 / 无匹配`。
按第 1 行实测，在 `web/` 下该命令的真实 rc 是 **2**，不是 1。

## 2. 根因（两个独立缺陷叠加）

1. **cwd 敏感**：命令中的通配 `web/*.config.*` 是相对仓库根写的，而 §11.3 的实测 cwd 是 `web/`。
   在 `web/` 下该通配**不展开**，grep 收到字面量文件名 → `No such file or directory` → **rc=2**。
   rc=2（命令自身错误）被误记为 rc=1（无匹配），于是「端口纪律自证」沦为**假绿**。
   同一处守卫在 §9 G7（138 行）当年曾诚实留痕「首跑 rc=0 命中 5 行注释」；后来注释字面量被清掉，
   但编排器落地 `/api` proxy 时又在 `vite.config.ts:32` 写回了 `3000/3001/3002`，守卫遂再次漂移。
2. **判据过宽**：`grep '300[012]'` 匹配**任意文本**，含注释。NOTE-01 的纪律意图是
   「配置文件不得把 dev server / proxy 的**端口值**设成 3000/3001/3002」，而非「文件里不许出现这三个数字」。
   `vite.config.ts:32` 的命中是**端口探测结论的事实留痕**（宿主 3000/3001/3002 实测 BUSY），
   与 `state.json -> decisions.dev_proxy_target` 互为交叉引用；删掉它等于销毁证据。

## 3. 处置（编排器裁定）

1. **不改写历史行**（依 D-012/D-013/D-014「历史值只加注不改写」）：§11.3 G6 原行保留，
   在 `M0-03-design.md` 文末追加 §11.5 纯增量追注块说明本单。
2. **不删 `vite.config.ts:32` 的注释字面量**：它是 NOTE-01 的证据，不是配置值。
3. **守卫重定义为两条**，一律在**仓库根** `/home/szf/dev/CampaignLab` 执行：
   - `G6a`（意图精确，期望 rc=1 无匹配）：
     `grep -rnE '^[[:space:]]*(port|target)[[:space:]]*:.*300[012]' web/*.config.*`
   - `G6b`（字面量白名单，期望恰好命中 1 条且为 `web/vite.config.ts:32` 注释）：
     `grep -rn '300[012]' web/*.config.*`
   两条本次均已实测：G6a rc=**1**（无匹配）、G6b rc=**0** 命中 **1** 条，结果记于 §11.5。
4. **cwd 口径入纪律**：`resume.dispatch_requirements` 已含「守卫命令一律在仓库根执行」，本单补其判据：
   凡 grep 守卫使用相对路径通配（`web/*`、`src/*` 等），派单文与 design 表格**必须同时写明 cwd**；
   rc=2 一律判「命令未跑起来」，禁当作 rc=1「无匹配」记账。

## 4. 防复发

- 门禁表每行必须记 **cwd + 命令 + rc + 关键输出**四元组；缺 cwd 的行视为无效证据。
- rc 语义严格区分：`0` = 有匹配；`1` = 无匹配（守卫期望）；`2` = grep 自身错误（**必须判红并修命令**）。
- 编排器复验 lane 门禁时，对一切「rc=1 无匹配」型守卫**必须在仓库根亲自重跑**，不得采信自报 rc。
