## 2. 定性：证据**未缺失**，是索引不完整 + 四处计数失真

关键区分（避免误判为取证不全）：

1. **12 号确被驱动**：`12-neg-bad-host-403.http` 在盘（17 行 / 462 B），内含完整请求与 `HTTP/1.1 403` + `ORIGIN_DENIED` 响应体；且 `98-run-summary.json` 有对应结果字段 `results.neg_bad_host = {status:403, code:"ORIGIN_DENIED"}`。
2. **20 号确被驱动**：`20-health-unmigrated-degraded.http` 在盘（17 行 / 382 B），内含 `HTTP/1.1 200` + `{status:"DEGRADED", worker:"READY", schema_revision:"UNMIGRATED"}`；对应 `results.fu7 = {status_code:200, body:{...UNMIGRATED}}`。这正是 **FU-7 的唯一取证件**，缺它 AC-034/FU-7 就不成立 —— 所幸它没丢，只是没进索引。
3. **13 号是空号，不是丢件**：全 `evidence/M0/**` grep 无任何 `13-*.http` 的引用或承诺；`commands.md:4` 提到的 `V13` 是 **S2 的 V 编号体系**（Q7/V1–V13 校验项），与 `http/NN-*.http` 的**文件序号体系无关**，两者被摘要混为一谈是失真来源之一。
4. **23 与 19 的差额（4）无证据**：疑为启动轮询探针（`boot_wait_seconds=0.8`，显式轮询 `/health`）与 FU-7 服务 B 的启停探测，这些**未落盘为证据件**，因此不可作为「请求数」计入证据面。按手册「禁估算、只记可复核值」，一律改记 **19 件落盘 / 17 条原索引**。
