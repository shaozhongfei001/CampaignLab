# D-039 · 派单 gate 命令不自带 provision，在裸克隆树上达不到自己的期望值：gate1 `bash scripts/doctor.sh` 期望 RESULT=HEALTHY 实得 PASS=3 WARN=2 FAIL=0 RESULT=DEGRADED；gate4 `alembic current` 期望 head=0001_initial_schema 实得 rc=0 但无 revision 行。根因是默认 data dir `~/.local/share/campaignlab` 不存在。构成每个 wave 出口的常驻假 RED 风险。

- **发现方**：Q lane Newton（Q-VERIFY-WAVE1，P-1 / B3）；编排器复核确认并上调严重度
- **发现时点**：2026-11-14T03:59:07+08:00
- **严重度**：MAJOR　**blocking**：false　**status**：OPEN
- **归属任务**：编排器（门禁目录 / Q lane 派单文模板）
- **owner**：编排器（门禁目录 + 派单文模板；`scripts/**` 属编排器写权，lane 被 deny）
- **权威证据**：evidence/M0/Q-VERIFY-WAVE1/raw/gate1-doctor.txt、raw/gate4-alembic-current.txt、raw/q-cmdlog.jsonl（H1/H2/H3）；evidence/M0/M0-02/ac.md:5（S5 的注入先例）；对照 evidence/M0/ORCHESTRATOR/r10d-volta-s3/raw/G14_doctor.txt（RESULT: HEALTHY）与 G14b_cli_doctor.txt（PASS=3 WARN=2 FAIL=0 DEGRADED）—— 两个 doctor 面结论不同属既有口径（rule_same_name_tools 要求分字段记录），本缺陷的修复须同时覆盖两面。

## 1. 现象与实测

按派单原文执行：doctor → `PASS=3 WARN=2 FAIL=0 RESULT=DEGRADED`（raw/gate1-doctor.txt）；`alembic current` → rc=0、无 revision 行（raw/gate4-alembic-current.txt）。补 provision 后（`CAMPAIGNLAB_DATA_DIR=/tmp/qverify-data` + 建 OPERATIONS.md 的 7 个子目录 + `uv run --no-sync alembic -c migrations/alembic.ini upgrade head`）：doctor → `PASS=5 WARN=0 FAIL=0 RESULT=HEALTHY` rc=0；`current` → `0001_initial_schema (head)` rc=0（raw/q-cmdlog.jsonl tags H1/H2/H3）。

## 2. 根因

gate 命令的**环境前置条件**未随命令一起下发。`scripts/doctor.sh` 与 `alembic current` 都读取默认 data dir（`~/.local/share/campaignlab`），该目录在全新环境里不存在；S5 lane 当初取证时用 `CAMPAIGNLAB_DATA_DIR` 注入（evidence/M0/M0-02/ac.md:5），但派单文抄命令时漏掉了注入步骤，于是期望值（来自注入后的环境）与命令（在裸环境执行）不自洽。

## 3. 责任归属

编排器侧：派单文把 gate 命令与其期望值当成一对契约下发，却未验证该命令在裸树上能否产出该期望值 —— 命令隐含依赖了宿主既有状态（已 provision 的 data dir）。lane 侧无责：Q lane 不仅如实报出偏差，还自行补 provision 复现了期望值并反证 S5 的 HEALTHY 自报为真。

## 4. 阻塞性判定

不阻塞产品交付：代码行为正确（未迁移的默认 data dir 本就应该报 DEGRADED，doctor 的提示可操作）。阻塞的是**门禁可复现性** —— 本项目共 11 个 wave，每个 wave 出口都要派 Q lane 跑同一批 gate，若不修则每轮都会产生一次假 RED 与一次人工归因，复利面大，故 severity 由 lane 建议的 Medium 上调为 MAJOR。

## 5. 修复范围

① 门禁目录（`resume.self_check_gates_rc0.gates` 的 G14 / G14b / alembic 类条目的 cmd 字段）；② Q lane 派单文模板（`orchestrator/handoff/Q-VERIFY-*-brief.md` 的 gate 段）；③ 新增固化规则 `rule_gate_command_must_be_self_provisioning`。不动产品代码、不动 `scripts/doctor.sh` 的判定逻辑（其行为正确）。

## 6. 修复方案

待实施。修复形态：gate 命令改为自带 provision 前缀（scratch `CAMPAIGNLAB_DATA_DIR` + 建 7 子目录 + `upgrade head`）再断言期望值；**不采用**「把期望值放宽为裸树 DEGRADED」的方案（A159：那会把真实故障态洗白成通过判据，削弱 AC-035 与 FU-7 的 UNMIGRATED 取证面）。派单前置检查新增一条：每条 gate 命令连同其期望值必须在裸克隆树上复现，跑不出即判派单缺陷。
