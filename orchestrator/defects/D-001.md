# D-001 契约切片工具 --tables 静默返回 NOT_FOUND

- 严重级：MAJOR（曾长期静默，未影响已交付切片，但会污染 M1–M4 所有 DDL 相关门禁）
- 发现者：Lane T（编排器），在断电恢复复验中通过「与 HEAD 版本做差分回归」暴露
- 受影响对象：`scripts/contract_slice.py` 的 `slice_tables()`；下游为所有用 `--tables`
  生成表结构切片的任务（M0-02 首迁比对、M1 导入表、M2 规则表、M4 导出/审计表）
- 复现：
  `python3 scripts/contract_slice.py --tables workspaces --out /tmp/x.json`
  实际：`/tmp/x.json` 内 `ddl.workspaces == "NOT_FOUND"`，进程 rc=0
  预期：返回 `CREATE TABLE workspaces (...) STRICT;` 原文块
- 根因：参考 DDL `spec/CampaignLab-SDD-v1.0/contracts/sqlite-v1.sql` 的 28 张表一律以
  `) STRICT;` 结尾，旧正则把终止符写成 `"\n);"`, 永不匹配；`grep -n "^)"` 显示 28 处全是 `) STRICT;`。
- 修复（同一提交内完成）：
  1) 终止符改为 `r"[\s\S]*?\n\)[^;]*;"`，兼容 `)` 后跟任意表选项再分号；
  2) 表头模式常量化 `table_head()`，避免再次拼错；
  3) 新增 `--all-tables` 与 stderr 摘要中的 `ddl_not_found=[...]`；
  4) 任一 NOT_FOUND 时 `raise SystemExit(2)`，把静默失效变成硬失败；
  5) 新增 `tests/unit/test_contract_slice.py` 8 例钉死：表数分母 28、无 NOT_FOUND、
     每块以 `CREATE TABLE` 开头且以 `STRICT;` 收尾、索引语句 6/6 全覆盖、未知表为 NOT_FOUND、
     operationId 切片与 AC 行原文切片可用；
  6) 顺带完成该文件的 mypy strict 类型化（断电前遗留 22 个 `no-untyped-def`）。
- 验证：差分回归显示 `--ops/--ac/--ui` 输出与修复前逐字节一致（正确行为未变）；
  金样本 `M0-02.slice.json`、`M0-03.slice.json` 重跑后仍逐字节一致；`--all-tables` 得 28/28。
- 状态：已修复并复验（rc 见 recovery-2026-11-12.md 第 4 节）。待 M0 阶段 Q 交叉验证时复核本单。
