## 1. 现象与实测

design §11.3 的第 4 条（1067–1071 行）要求 `api/app.py` 在 **S2** 阶段追加：

> `create_app` 追加两个可注入形参 `activity_service` / `rule_service`（默认 `None`，不注入就不装配）
> ＋ 两行 `app.state.<name> = <service>` ＋ **两行 `app.include_router(<router>)`**（条件与既有 `if workspace_service is not None:` 同形）

但那两个 `<router>` 的真值来源分别是 `api/activities.py`（§11.4 标题明写「S3，**只新建**」）与
`api/rules.py`（§11.5 标题明写「S4，**只新建**」）。而 A210 与 A196 ① 把 M2-01 的子任务序**固定**为
S2a → S2b → S3 → S4 → S5 → S6 → S7。

⇒ **在 S2b 的时间点上，这两个 router 所在的模块还不存在。** 照 §11.3 字面实现只有两条路，两条都是红的：

- **路 A**：写 `from campaignlab.api.activities import router as activities_router` —— 模块 ABSENT，
  `mypy` 在 strict ＋ `warn_unused_ignores` 下直接 `import-not-found` 判红；若加 `# type: ignore` 绕过，
  运行期 `create_app` 一调用即 `ModuleNotFoundError`，且该 ignore 在 S3 落地后变成**无用 ignore**，
  又被 `warn_unused_ignores` 判红（这正是 A207 在 `worker/deps.py:55` 上踩过的同一形态）。
- **路 B**：自行发明两个 stub 模块 —— 越出 §11.4/§11.5 划定的写权（「**只新建**」归 S3/S4），
  违反手册 §6.4「不得越出下列文件与符号，越界即回报编排器」，且会与 S3/S4 的成品产生二次冲突。

## 2. 根因

**设计文档在「按文件切分写权」与「按时间切分子任务」两个维度上未对齐。**

§11.3 的标题是「S2 **附带的**应用层与基础设施层」——它把 `api/app.py` 归给 S2 的理由是**写权归属**
（`api/app.py` 的 A90①/A10 最小例外额度在这一节一并申请）；但 `include_router` 这一行的**可执行前提**
是运行期依赖（router 对象存在），属于**时间维度**。文档只按前者归类，没有检查后者的可满足性。

同一文档里其实**已有正确的成例**：`api/app.py` 第 156 行现存的注释占位
「M0-04/S4（A10 最小例外，≤3 行）：`app.include_router(jobs.router)`」——即 M0-04 的 router 挂载
**随创建 `api/jobs.py` 的那个子任务（S4）走**，而不是提前到 M0-04/S2。§11.3 未沿用这个成例。

**这不是任何 lane 的过错**：设计文档由 M2-01/S1 产出，S1 的职责是「只设计、不含实现代码」，
其自检（§13）跑的是命令 rc 与符号实取，**无法**照出「跨子任务的运行期依赖时序」这一类矛盾。
