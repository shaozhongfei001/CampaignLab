# D-009 · 编排器用 `isinstance(dict)` 守卫写 state.json，实际结构是 list，导致 D-006/D-007/D-008 与 CR-002 静默未入账

- 严重度：**MAJOR**（账本完整性；静默失效——无异常、无日志、无失败信号）
- 状态：FIXED_PENDING_Q
- 发现时间：2026-11-13T00:30:19+08:00
- 发现者：编排器本体（执行 CR-002 裁定入账时抛 `TypeError: list indices must be integers or slices, not str` 才暴露）
- 证据：本文件 + `tests/unit/test_state_ledger.py`

## 1. 现象

`orchestrator/state.json` 中：

- `defects` 是 **list[dict]**，每条形如 `{"id":"D-001","task":"M0-01","severity":"MAJOR","status":"FIXED_PENDING_Q","file":"orchestrator/defects/D-001.md"}`
- `change_requests` 同样是 **list[dict]**，形如 `{"id":"CR-001","task":"M0-P01","status":"ACCEPTED","adr":"ADR-004","nodes":12,"file":"..."}`

而编排器前几轮的写入代码形如：

```python
if isinstance(st.get("defects"), dict):
    st["defects"]["D-006"] = {...}  # 守卫为假 -> 整段被跳过
st.setdefault("change_requests", {})
if isinstance(st["change_requests"], dict):
    st["change_requests"]["CR-002"] = {...}  # 守卫为假 -> 整段被跳过
```

`isinstance` 为假 → 分支不执行 → **不报错、不告警、提交照样成功**。

## 2. 影响

`D-006`、`D-007`、`D-008` 三个缺陷单与 `CR-002` 只存在于：

- 各自的 `.md` 文件（`orchestrator/defects/D-00{6,7,8}.md`、`orchestrator/change-requests/CR-002.md`）
- 提交信息文本（`ce2d9fa`、`de550a5`、`ee51f3f`）
- `resume.next_actions` 的自然语言描述里

但**账本（`state.json` 的 `defects` / `change_requests`）里查不到**。后果：

1. 任何按手册第 10 节恢复协议、以 `state.json` 为唯一真值接管的新实例，会**漏掉这三个缺陷与一个 CR**，
   可能重复修复、或误判"无未决缺陷"而放行。
2. Q 判定档受托"逐个判定 D-001..D-008 是否 CLOSED"，若它从账本取列表，只会看到 D-001..D-005。
3. 这正是手册 **15.3** 所禁止的「被文字引用到的键必须真实存在」的变体：
   引用存在于提交信息与 next_actions，账本却悬空。

## 3. 根因（方法论层面，比代码错误更重要）

用 `isinstance` 做**容错守卫**时，把"结构不符合预期"当成了"那就跳过"，
而正确语义应当是"结构不符合预期 = 立即失败"。在无人值守长程里，
**静默跳过比崩溃危险得多**：崩溃会被发现，跳过不会。

## 4. 修复

1. 改用**结构感知 upsert**：按 `id` 匹配，存在则合并字段、不存在则追加；对 list 与 dict 两种形态都成立。
2. **写入后必须回读断言**：`re-read state.json` 并断言目标 id 确实在账本内，否则抛异常阻止提交。
   本次实测回读结果：`defects = D-001..D-009`（9 条）、`change_requests = CR-001, CR-002`（2 条），断言 PASS。
3. 补 `D-006/D-007/D-008/D-009` 与 `CR-002` 的完整账本条目（含 severity、status、ref、fix_commit、
   regression_guard、evidence 等字段，与既有条目形态兼容）。
4. 新增 `tests/unit/test_state_ledger.py` 做**双向**守护（见第 5 节）。
5. 手册 15.3 增补条款：账本写入必须回读断言，禁止用 `isinstance` 静默跳过。

## 5. 回归测试钉住的不变量

`tests/unit/test_state_ledger.py`：

1. `state.json` 可解析，且 `defects` 与 `change_requests` 必须是 **list[dict]**、每条含非空 `id`
   （结构假设被显式钉住，今后谁改结构谁先红）。
2. **账本 → 磁盘**：每条 defect 的 `id` 必须有对应的 `orchestrator/defects/<id>.md` 存在（不得悬空引用）。
3. **磁盘 → 账本**：`orchestrator/defects/` 下每个 `D-*.md` 都必须在账本里有对应条目
   （不得出现"有文件无账本"，即本缺陷的形态）。
4. `id` 不得重复；`D-*` 编号必须连续无缺号（缺号即 rc 失败，属**分母断言**）。
5. 每条 defect 必须含 `severity` 与 `status`，且 `status` 取值在允许集合内
   （`OPEN` / `FIXED_PENDING_Q` / `CLOSED` / `WONT_FIX`）。
