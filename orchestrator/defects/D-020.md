## 1 现象（实测，非转述）

`scripts/contract_slice.py` 的 `refs_of()` 在 `depth == cap` 时把 `$ref` 指向的组件写成字符串
`"TRUNCATED"`，而 CLI 的 `--depth` 默认值是 **2**。7 份切片实测命中数：

| 切片 | 旧 bytes | 旧 sha16 | `"TRUNCATED"` |
|---|---|---|---|
| M0-02.slice.json | 14493 | `a06b4941fd35b39d` | 1 |
| M0-03.slice.json | 16165 | `b2aaba68adef8747` | 1 |
| M0-04.slice.json | 23095 | `8dc116f109a51c14` | 7 |
| M3-01.slice.json | 15681 | `64d79b599bfe60d9` | 8 |
| M3-02.slice.json | 27184 | `3d55ec5497916343` | 8 |
| M3-03.slice.json | 15284 | `ea5be2b20dc1d21f` | 11 |
| M4-01.slice.json | 26466 | `152c5fd4951eb584` | 9 |
| **合计** | | | **45** |

被截断的正是 `Problem` / `Issue` / `ObjectRef` / `Job` / `JobPage` 这类**核心 schema**——
即错误响应体与作业体的逐字段口径。

## 2 为什么是 MAJOR 而不是 MINOR

1. **静默**：`missing_targets()` 只校验「请求的 id 有没有切到」，`"TRUNCATED"` 是一个合法字符串值，
   于是 rc=0、文件照常写出、派单照常进行。手册 13.3 / 15.4 的「禁止静默失效」被绕过。
2. **成本失控且已实际发生**：lane 拿不到字段口径只能回读 443309 B 的活契约。
   M0-04/S1（Heisenberg）自报 token **56k**，超 45k 预估 **+11k**，其上报的 N1 明确归因于此。
3. **质量风险**：flash 档 lane 若照「严格按设计」执行而设计文档也没展开该 schema，
   就只能凭记忆补字段——这正是 D-011/D-012 要杜绝的「写死/杜撰」。

## 3 修复（三处，均已实测）

1. `DEFAULT_DEPTH = 5`（原 `--depth` 默认 2）。**论证**：对全部 7 组参数分别以 depth=5 与 depth=6
   重切，产出**字节完全相同**（7/7 True），故 5 层已覆盖活契约最深的 `$ref` 链，6 层无增益。
2. 输出顶层**恒有** `truncated_schemas` 清单（无截断时为 `[]`），使消费方可以断言、
   也使 `sections=[...]` 的 stderr 统计自带该维度。
3. `truncated_schemas` 非空一律 **rc=2 且不写出文件**，与既有「目标未命中 rc=2」同一处置口径。
   截断从此不可能再静默发生。

`refs_of()` 增加可选形参 `truncated: set[str] | None = None`；传 `None` 时退化为旧行为，
供只想探测不想收集的调用方使用（既有 22 个单测的调用形态未受影响）。

## 6 回归守卫设计要点

6 个新函数覆盖三件事，缺一则守卫形同虚设：

1. **默认深度足够**：`test_d020_default_depth_is_five` 钉死 `DEFAULT_DEPTH == 5`；
   `test_d020_all_dispatched_op_sets_expand_without_truncation` 以 parametrize 对 **6 组已派发
   operationId 集合**逐一断言 `truncated == set()` 且递归扫描无任何哨兵值；
   `test_d020_core_schemas_are_real_objects_at_default_depth` 断言 `Problem`/`Issue`/`ObjectRef`/`Job`
   四个核心 schema 在默认深度下是**真实 dict**而非哨兵。
2. **截断必被登记（守卫自证）**：`test_d020_shallow_depth_does_register_truncation` 以 depth=1
   断言 `truncated` **非空**。一条永不触发的守卫等于没有守卫，第 1 类的绿灯将毫无意义。
3. **登记必致 rc=2 且不产出文件**：`test_d020_cli_shallow_depth_exits_2_and_writes_nothing`
   断言 rc=2、`out.exists()` 为 False、stderr 含 `D-020` 与 `truncated_schemas`；
   `test_d020_cli_default_depth_emits_empty_truncated_schemas` 断言默认路径 rc=0、
   `truncated_schemas == []`、stderr 含 `truncated_schemas=[]`。
