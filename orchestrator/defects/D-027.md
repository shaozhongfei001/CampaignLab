## 2. 缺陷定性

两个形态，同一危险等级：

- **形态一（校验不完整）**：编排器把「lane 在飞禁跑工具链」（NOTE-10）的约束沿用到了 lane **已全部回报**之后。
  两个 lane（Godel/S3d、Planck/批次4）当时都已交付，工具链早已解禁，前提不再成立却未重新评估，
  于是提交前只跑了不依赖 `.venv` 的 pytest 与纯 python3 守护直调，漏掉 lint/type/format 三项。
  结果：一个带 11 处 ruff + 2 处 mypy + 1 处 format 违规的文件被入库并推送。
- **形态二（rc 采集失真）**：门禁命令写成 `cmd 2>&1 | tail -N` 后，shell 管道的退出码取自**最后一个命令**（`tail`，恒 0），
  于是 `assert rc == 0` 变成恒真断言。本次 `ruff check` 与 `ruff format --check` 双双假绿。
  这与 D-009 的定性同类：**在无人值守长程里，静默的假绿比崩溃更危险**——它会让后续所有提交都以错误的基线为准。

## 3. 处置（本提交内完成）

1. **前向修正**守护文件（禁 force-push、不改写历史）：超 100 字符行改写、`zip(ids, ids[1:])` → `itertools.pairwise(ids)`、
   新增 `_wave_no()` 做整数断言以消除 `Any | None`、按 `ruff format` 折行两处 `assert`。修正后四项工具实测全绿（第 1 节第 8/9 行）。
2. **rc 采集口径固化**（写入 `state.json -> resume.gate_measurement_caliber`）：
   - `rule_rc`：门禁命令一律 `set -o pipefail` 或干脆不接管道（输出过长时在 Python 侧截断）；rc 必须由被测命令本身产生。
   - `rule_double_judge`：**rc 与输出文本双判**，任一不符即判红——pytest 匹配 `N passed` 且不含 `failed`；
     ruff check 含 `All checks passed`；ruff format --check 匹配 `N files already formatted` 且不含 `would be reformatted`；
     mypy 含 `Success: no issues found in N source files`；doctor `RC=0` 且逐项核对 PASS/WARN/FAIL；
     check_contracts 含 `CONTRACT CHECK PASS` 且登记项 == 实测差异。
   - `rule_precommit_full_table`：提交前必须跑全表；**lane 全部回报即解禁工具链**；任一未跑必须在提交信息写明「未跑 + 原因」。
   - `rule_new_file_gate`：编排器自己新写的 `.py`/`.md` 入库前必须先过 ruff format + ruff check + mypy（`.py`）与 BOM/CR/尾换行（全部）。
3. `state.json -> resume.round6_self_corrections` 登记 **R6-1**（校验不完整）与 **R6-2**（rc 采集失真），
   均含 root_cause / corrective_action / evidence / impact_if_missed，原值不改写。
