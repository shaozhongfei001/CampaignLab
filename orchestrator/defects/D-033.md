## 1. 现象（实测）

同一 `Idempotency-Key` + 同一请求摘要重放 `createWorkspace` 时：

| 面 | 首次（新建路径） | 重放路径 | 是否一致 |
|---|---|---|---|
| 状态码 | 201 | 201 | 一致 |
| `ETag` | `"1"` | `"1"` | 一致 |
| 正文语义（字段集与值） | Workspace DTO | 同一 Workspace | 一致 |
| **正文字节序** | 按 DTO 声明序（`{"id":...}` 开头） | 经 `common.replay_from_envelope` 的 `json.dumps(信封 body)`，呈字典序（`{"authorization_note":...}` 开头） | **不一致** |

即：`tests/api/test_contract_http.py::test_idempotency_replay_is_byte_identical_and_writes_once` 实测
`first.content != second.content`，Bohr 未按卡面要求判红，而是**降级为语义等价断言**并在 docstring 留证上报。

## 2. 定性与影响

- M0-02 卡 S4 行与 design 均要求「同键同摘要重放返回**逐字节相同**的响应（含 ETag）」；ADR-005 §2.1 的幂等信封单点也以此为前提
- 实际影响有限：状态码、ETag、字段集与值全部一致，语义等价；但**任何按字节比对正文的客户端或证据脚本会判不等**，且 AC-034 的「重放一次生效」若以字节取证会失败
- 不阻塞本轮：S4 的 51 项用例全绿，其余幂等语义（只写一次、409 异摘要冲突）均已机器钉住

## 3. 处置（FU-21，归 Round 9）

统一正文序列化出口：让新建路径与重放路径共用同一个 `json.dumps` 口径（同一 `sort_keys` / 同一字段序来源），
落点在 `src/campaignlab/api/common.py`（`replay_from_envelope` 与其对偶的响应渲染）或 `application/` 的信封组装处。
`api/common.py` 属 public_frozen（A77/A78），故修法须走 **append-only 豁免或 CR**，派单文须显式授权。
修复后把上述用例的断言从「语义等价」收回到「逐字节相同」（`first.content == second.content`），**禁删除该用例**。

Bohr 的处置**正确**：发现实现缺陷后不擅自改 `src/**`（越界）、不删用例、不降门禁，改为语义等价断言 + docstring 留证 + 上交裁定。
