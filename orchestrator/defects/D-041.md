# D-041 · 三张任务卡缺失（M3-P02 / M5-P01 / M5-03）：台账有任务、有依赖、有 wave 归属，但 orchestrator/tasks/ 下无卡 → 手册 15.5「无拆解表不得 spawn」使 wave7/9/10 无法派单

- **发现方**：lane T（Peirce）—— 按派单文「目标必须从任务卡取、缺卡即上报 U 项禁猜」如实上报；编排器独立复验确认
- **发现时点**：2026-11-14T04:59:18+08:00
- **严重度**：MAJOR　**blocking**：false　**status**：OPEN
- **归属任务**：GOVERNANCE
- **owner**：编排器（补卡）
- **权威证据**：编排器实测 `ls orchestrator/tasks/` = 26 张卡（M0-01 M0-02 M0-03 M0-03b M0-04 M0-P01 / M1-01 M1-02 M1-03 M1-04 M1-P01 / M2-01 M2-02 M2-03 M2-04 / M3-01 M3-02 M3-03 M3-04 M3-P01 / M4-01 M4-02 M4-03 M4-P01 / M5-01 M5-02）—— **M3-P02.md、M5-P01.md、M5-03.md 三者不存在**；而 `state.json -> tasks` 有 29 个任务键，其中 M3-P02（deps=M0-03,M3-P01,M3-04，wave7/L4）、M5-P01（deps=M3-P02,M4-P01,M5-01，wave9）、M5-03（deps=M5-02,M5-P01，wave10，serial）三者均在册且**均在 critical_tasks 名单内**（M5-P01 与 M5-03 属关键路径）。

## 1. 现象与实测

缺口规模 = 3 / 29 任务（10.3%）。同族对照：M3-P01.md 与 M4-P01.md **均已存在**，说明 P 系列（v1.0.1 月报增量）的建卡模式早已建立，本缺口属**遗漏**而非「设计上留待后续」的有意安排。lane T 的 9 张切片任务因此只产出 6 张（M1-01/02/03、M2-01/02/03），余 3 张（M3-P02、M5-P01、M5-03）**无卡即无 ops/ac 目标来源**，lane 按派单文禁猜、如实上报为 U 项。

## 2. 根因

建卡是编排器的治理动作，v1.0.1 补丁合入时（M0-P01，2026-11-12）只补了当时即将派单的 P 卡（M3-P01 / M4-P01），未对 `state.json -> tasks` 与 `orchestrator/tasks/*.md` 做**全集对账**；此后 10 轮派单都只消费「已有卡」的任务，缺口因此一直未被任何门禁照到 —— **根因是缺少一条「台账任务集 == 卡文件集」的守护**，而不是某一轮的疏忽。

## 3. 责任归属

编排器（治理产物缺口）。lane T **无责且表现正确**：派单文明载「不确定即上报 U 项、禁猜」，lane 严格照办，未自行发明 ops/ac 目标，也未擅自读 spec/** 去凑 —— 这正是 A159 「禁让判据在缺输入时静默通过」的期望行为。

## 4. 阻塞性判定

**当前不阻塞**：三张卡的消费点分别是 wave7（M3-P02）、wave9（M5-P01）、wave10（M5-03），当前进度在 wave2；wave3（M1-01..03 / M2-01..03）的 6 张切片本轮已全部产出。**但它是 wave7 派单的硬前置**：手册 15.5「无拆解表不得 spawn」，无卡即不得派单，届时若未补，关键路径（M5-P01、M5-03 均在 critical_tasks 内）会直接停摆。故 blocking=false 但 **trigger 硬约束 = M3-P02 派单前（即 wave6 出口之前）必须闭合**。

## 5. 修复范围

orchestrator/tasks/{M3-P02,M5-P01,M5-03}.md（3 张新卡）+ 新增一条守护用例（台账任务集 == 卡文件集）

## 6. 修复方案

① 三张卡按既有 P 卡体例撰写（对照 M3-P01.md / M4-P01.md 的结构：任务目标 / inputs / scope_allow / scope_deny / 子任务档位表【手册 15.5 四列硬约束：子任务／档位／预估 token／写权落点】/ 门禁表 / AC 归属）；AC 原文权威路径 = spec/CampaignLab-SDD-v1.0/qa/ACCEPTANCE.md，月报增量 AC 另给 spec/CampaignLab-SDD-Patch-v1.0.1-Monthly-Review-Delta/qa/ACCEPTANCE-MONTHLY.md（A133 口径）。② **M5-03 特殊**：它是「用户确认」节点，卡内必须显式标注 `human_only_action`，禁把人类确认动作派给任何子智能体自证通过。③ 卡写完后补切 3 张切片（复用 lane T 的口径，含 A170② 的 `__indexes` 剔除规则）。④ 新增守护：`tests/unit/test_task_cards_complete.py` —— 断言 `state.json -> tasks` 的键集与 `orchestrator/tasks/*.md` 的文件名集**完全相等**（双向），使本缺口不可能再次静默存在。该守护属编排器治理面，归 FU-33。
