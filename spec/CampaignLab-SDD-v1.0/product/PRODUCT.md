# 产品范围与业务流程

## 使用者与职责

| 角色 | 任务 | 授权动作和交付 |
|---|---|---|
| 活动策划 | 理解原条款、记录歧义、形成候选版本 | 编辑草稿、提交复算、提供人工确认预期 |
| 指标与数据负责人 | 维护接入映射、时间窗口和定义 | 校验导入并发布本地数据快照，提供定义证据 |
| 分行或渠道运营 | 比较两期、识别偏差、形成改进 | 选择范围、读分母与源记录、登记假设和下一步责任 |
| 验收人员 | 检查案例、原规则和预发 | 对照实际与预期，记录有来源的结果 |
| 报告审核者 | 核对范围、指标、证据和待补事项 | 签认指定版本，查看补数修订与下期复核 |
| 本机操作员 | 安装、迁移、备份、恢复及授权导出 | 管理本机工作区和任务。首版由一个本机用户按业务角色记录操作 |

## 两条首版业务流程

### 流程 A 满额赠券

创建活动 → 引用条款并确认业务口径 → 建立原方案和候选版本 → 查边界、预算、重复和叠加 → 同样本并排运行 → 查看首个差异、券状态、次数与预算账本 → 按确认的预期生成验收案例 → 导入模拟预发 → 审阅差异与归档证据。

新客起算、金额定义、时间端点、叠加、预算和退款必须显式确认。方案 A 保留已发券，方案 B 在退款后低于门槛时撤回未用券。已核销转人工处理，当前分录保留。均为本包的合成规则。

### 流程 B 远程回拨

分别导入两家银行 → 核对映射和数据覆盖 → 对账同义指标和推送口径差异 → 生成本期复盘 → 发现有效触达少 192 人 → 查看量率与分支下钻 → 形成预约优先改案 → 校验原规则复跑一致 → 保存候选验收案例 → 导入预发与行内版本回执 → 查看下期 → 签认报告与复核动作 → 迟到补数后保留两版证据。

复盘页事实来自快照。试算来自明确假设。诊断提供统计拆解与核查线索。下期对比为观察。对照实验或获认可的因果证据另行关联，净增量结论由审核者确认。

## 功能覆盖

| 功能域 | 最小可验交付 |
|---|---|
| 活动与规则 | 活动列表、版本状态、来源条款、活动与策略绑定、规则检视、差异和确认 |
| 数据与口径 | 导入任务、映射字段、版本与源行、渠道规则、时间窗归属、跨行对账 |
| 仿真与验收 | 场景输入、原规则实测或显式预期、批量与单例复跑、轨迹、差异、预发和回执 |
| 策略复盘与诊断 | 三块复盘、六渠道与全渠道、专题、阈值、维度和量率、登记问法 |
| 报告与改进 | 七段与专题、取数清单、签认和更正、改进项、下期复核 |
| 工作区 | 本机运行、作业、审计、导出、备份与恢复 |

[验收基线](../qa/ACCEPTANCE.md) 是实施的完成条件。[原型点位追踪](TRACEABILITY.md) 保留 55 个材料点位、47 个手册操作点和新增领域验收。

## 状态提示

数据和计算使用「完整可比」「部分可比」「待补数据」。规则冲突使用「待确认」「可复测」「需复测」。预发比较使用「待导入」「一致」「差异」「缺项」「版本不符」。显示文案按 [公共页面规范](../ui/COMMON.md) 与各页契约映射。状态来源为服务端和对应证据。
