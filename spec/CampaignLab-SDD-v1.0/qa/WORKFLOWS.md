# 本机 Codex 端到端走查脚本

以下是要实施并重跑的业务步骤。示例编号是 fixture alias。实际运行以创建响应返回的资源 ID 替换。证据记录按操作顺序串起 ID、摘要和观察，能够定位两次计算是否使用同输入。

## A 满额赠券

1. 在本机工作区新建合成项目和 COUPON-01 活动。调用 registerEvidence 记录条款证据，建立两个 rule 版本 CP-V1 和 CP-V2。使用 [规则夹具](../fixtures/cases/rules.json)。在编辑页给各约定填写来源和确认项。分别确认原版与候选版，保留确认摘要。
2. 打开规则检查，核对门槛、日期、初始次数、叠加、预算及退款。用 CP-01 至 CP-12 建确认案例。CaseCreate.input 使用夹具 input，expected 使用 expected_candidate。明确模拟结果由业务人员对照规则确认。
3. 运行两个已确认版本，核对逐条结果和轨迹。CP-07 的付款 12000 分，退款 2500 分。A 的已用、预算、券状态为 1、2000、ISSUED，B 为 0、0、REVOKED。CP-08 的 B 进入待人工，保留已用 1、预算 2000。CP-03 的重传和同订单累计只发一次。
4. 从 CP-07 保存候选预期，导入一次正确结果和一次差异，核对预发。变更规则版本后确认旧候选显示待复测。导出同一版本的证据包，并以文件清单验证摘要。
5. 额外输入逆序时刻、退款超额、双重不同 payload 的 event_id。确认输入被标记错误，其他有效行保持可见，错误行不能形成候选。

## B 远程回拨

1. 新建合成工作区并导入 bank-a.json 与 bank-b.json。验证并发布，在来源映射中对照两张实体表、乙行长表和单位。按下方的默认范围分别对账远程与推送。
2. 选择 A-001、2026-10、B01 东岚、remote 远程、上月环比，计算 Review。与 [分析夹具](../fixtures/analytics-golden.json) 对照。打开 15% 经营率、50% 末层率证据。把全渠道和 2026-01 环比分别作为部分可比及缺基准分支。
3. 在默认范围生成诊断，核查 −192 的贡献和两处下钻。另存阈值 12% 并验证期间触发变化。从问题「解释10月东岚远程渠道有效触达客户数下降的原因」定位到接触层，记录动作及 30 天验证。
4. 在试算页输入 45%。以 8,640 和 50% 固定计算 1,944。转到 AC-101 活动，绑定 S-101 V1 有效区间，确认回拨 V1/V2。用 SIM-017 至 019 建历史案例。将 observed_rule_id 绑定本地 CB-V1，observed_original 按夹具，来源登记 EXEC 样本。
5. 运行原规则与候选。SIM-017 原一致，候选为 S-101，保留验收案例。SIM-018 原结果不同。SIM-019 频次已用满。按预发向量比较并审阅匹配的 SIM-017，登记合成 REL-101。
6. 复制相同机构、渠道和指标，观察 11 月对 10 月。以 1,944 人及增加 216 人记录到改进项，并关联 PRE-101/REL-101 和案例。结果标「下期观察」。案例动作状态按契约先进入待验证再保存复核。
7. 从 10 月复盘生成报告，核对七段和签认摘要。保存签认，发布金额补数，按更正快照生成新报告。原始 AUM 为 −407400000 分，新值 −394900000 分。分别导出，检查旧签认与更正证据。
8. 在作业执行时中断进程，重启后核对失败态和重试。备份到新路径，再恢复到另一个目录。确认历史签认、作用域、制品与导出仍可查。
