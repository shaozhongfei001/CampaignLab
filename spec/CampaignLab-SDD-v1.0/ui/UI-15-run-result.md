# UI-15 运行结果、轨迹与验收案例

路由 `/w/:workspace_id/runs/:run_id`。导航为「仿真与验收」。适用角色为活动策划、验收人员。需求编号 FR-15。

理解哪个事件导致规则结果分歧，保存可移交的候选预期。

## 页面结构

| 区域 | 布局与内容 |
|---|---|
| 摘要 | 快照、输入、原规则、候选规则及摘要 |
| 主区 | 左 4 列案例列表，右 8 列双栏结果和轨迹 |
| 底部 | 验收预期确认、移交及导出 |

使用 [公共页面规范](COMMON.md) 的 12 列、状态、键盘与证据抽屉。下表以服务端模型为数据来源。

## 字段和绑定

| 区域 | 字段 | 接口模型 |
|---|---|---|
| 单例 | 原规则实测一致性、首个差异事件、两侧赢家或券账本 | RunCase |
| 逐事件 | 序号、时刻、规则原因、次数和预算增减 | TraceStep |
| 保存 | 选择 case_id、结果期望、人工说明 | CandidateCreate |

## 操作、接口与反馈

| 动作 | operationId | 提交和反馈 |
|---|---|---|
| 查看并切案例 | getRun, getRunCase, getEvidence | 获取摘要列表后按案例请求轨迹。对齐同 event_id 并标首个差异，用执行位置展示优先顺序 |
| 保存验收案例 | createCandidate, listCandidates | 用户核对预期和输入摘要，保存后可在预发页选择 |
| 导出本次证据 | createExport, getJob, downloadExport | 待制品完成后下载 |

## 页面状态与边界

- 历史原规则 DIFF 或 MISSING、输入错误、待人工处理或候选已失效时显示原因并禁止保存。SIM-017 可移交，SIM-018 原实测不符。
- 首载、空结果、失败、版本变化和权限状态采用公共页面规范。详情和制品以当前工作区校验结果为准。
