# UI-16 行内预发结果对照

路由 `/w/:workspace_id/preflight`。导航为「仿真与验收」。适用角色为验收人员、业务审核者。需求编号 FR-16。

把行内预发的实际结果逐例对照冻结的预期并记录审阅。

## 页面结构

| 区域 | 布局与内容 |
|---|---|
| 上方 | 活动、候选集合、预发来源和选择批次 |
| 全宽结果 | 候选、原与候选摘要、预期、实际、差异、状态 |
| 右侧抽屉 | 差异路径和来源证据 |

使用 [公共页面规范](COMMON.md) 的 12 列、状态、键盘与证据抽屉。下表以服务端模型为数据来源。

## 字段和绑定

| 区域 | 字段 | 接口模型 |
|---|---|---|
| 导入 | 选择案例集、批次、观察时刻、实际结果和原证据 | PreflightCreate |
| 判定 | 一致、差异、缺项、版本不符、待复测 | Preflight.rows |

## 操作、接口与反馈

| 动作 | operationId | 提交和反馈 |
|---|---|---|
| 创建预发记录 | listCandidates, registerEvidence, createPreflight | 粘贴结构化 JSON 或从文件读取到表单，服务器重新核验 |
| 审阅结果 | listPreflights, getPreflight, reviewPreflight | 提交当前摘要和说明。通过后前往活动详情登记回执 |

## 页面状态与边界

- 缺观察为 MISSING，摘要不同为 VERSION_MISMATCH，候选过期为 STALE。人工说明只补证据，结果由服务端重新判定。
- 首载、空结果、失败、版本变化和权限状态采用公共页面规范。详情和制品以当前工作区校验结果为准。
