# UI-17 策略复盘工作台

路由 `/w/:workspace_id/review`。导航为「策略复盘」。适用角色为分行运营、渠道运营。需求编号 FR-17。

核对参与度、五层漏斗和执行效果，识别最值得进一步核查的环节。

## 页面结构

| 区域 | 布局与内容 |
|---|---|
| 头部 | 范围条和快捷基准，右侧生成报告和下载 |
| 指标行 | 每张 3 列，覆盖率、名单执行率、有效触达数、有效触达率 |
| 中部 | 左 7 列五层漏斗，右 5 列优先核查和专题 |
| 下部 | 全宽参与度、执行效果、分行/渠道/支行/客群明细 |

使用 [公共页面规范](COMMON.md) 的 12 列、状态、键盘与证据抽屉。下表以服务端模型为数据来源。

## 字段和绑定

| 区域 | 字段 | 接口模型 |
|---|---|---|
| 范围 | 本期、基准、快照、截止、活动/策略及高级维度 | Scope |
| 指标 | 原值、分子分母、可比值、差值与变化率 | Review.metrics |
| 专题 | 部署客群/月末标签、意向/特色及 AUM | Review.topic_rows |

## 操作、接口与反馈

| 动作 | operationId | 提交和反馈 |
|---|---|---|
| 计算当前范围 | listSnapshots, runReview, getJob, getReview | 切明细维度后重新计算。低转化层突出，显示固定上月的参与度列 |
| 核对证据与优先项 | getEvidence | 点经营卡或漏斗层，抽屉区分触达经营率与层间率 |
| 发起报告或导出 | createReport, createExport, getJob | 沿同一个 review_id，成功后进入报告或证据页 |

## 页面状态与边界

- 本期有效触达 1,728，基准 1,920，差 −192。企微覆盖恢复时全渠道部分可比。活动绑定缺失或无基准时提供补数入口。
- 首载、空结果、失败、版本变化和权限状态采用公共页面规范。详情和制品以当前工作区校验结果为准。
