# UI-05 规则检查与边界案例

路由 `/w/:workspace_id/activities/:activity_id/rules/:rule_id/checks`。导航为「活动与规则」。适用角色为活动策划、验收人员。需求编号 FR-05。

集中处理规则缺口、重复与冲突，选择建议的边界案例进行验证。

## 页面结构

| 区域 | 布局与内容 |
|---|---|
| 范围条 | 活动、版本、摘要、待确认数 |
| 左 8 列 | 问题列表按错误、警告、信息排序 |
| 右 4 列 | 边界案例推荐和定位 |

使用 [公共页面规范](COMMON.md) 的 12 列、状态、键盘与证据抽屉。下表以服务端模型为数据来源。

## 字段和绑定

| 区域 | 字段 | 接口模型 |
|---|---|---|
| 问题 | 等级、规则字段、原因、来源条款、复核动作 | RuleCheck.issues |
| 建议案例 | 模板边界、按本版本生成的输入、需人工确认的预期 | RuleCheck.boundary_cases |

## 操作、接口与反馈

| 动作 | operationId | 提交和反馈 |
|---|---|---|
| 检查当前版本 | getRule, checkRule | 读取当前摘要的检查结果，不覆盖上一个版本结果 |
| 使用边界案例 | createCase | 预填模板输入，用户补充证据和预期后保存 |

## 页面状态与边界

- 有 ERROR 或待确认条款显示 NEEDS_CONFIRMATION。规则检查完成后的告警仍允许业务人员复核确认。边界输入只在匹配模板中提供。
- 首载、空结果、失败、版本变化和权限状态采用公共页面规范。详情和制品以当前工作区校验结果为准。
