# CampaignLab 跨银行接入设计约定

2026-11-11 · 发起人确认作为后续设计依据 · 银行接入效果待验证

## 系统职责

CampaignLab 是**营销活动规则仿真与上线前验证平台**。银行营销活动管理平台维护活动方案、正式规则版本、审批与发布流程。CampaignLab 引用指定版本的规则快照，基于合成或经授权的脱敏案例做试算、复跑及差异对照。不同业务假设在仿真副本中试验，正式规则的修改和确认由银行团队在行内平台完成。

## 跨行通用的接入方式

**统一仿真契约 + 每行一份接入配置 + 可选的只读连接器。** 首版优先文件导入，有联网取数需求时接既有的只读接口。接入层吸收字段、单位、代码值和数据通道的差异。CampaignLab 核心消费统一的活动规则快照、仿真案例及结果记录。一家银行的接入配置应在多个活动间复用，随来源接口和业务口径的变化独立更新。

- **绑定来源和版本。** 快照保留来源系统、行内活动编号、正式规则版本、生效时间及接入配置版本。仿真假设和正式规则分别记录。
- **保留业务差异。** 同义的元与分可以换算。按支付成功发奖与按入账成功发奖应作为不同的规则口径，由银行确认并用样例验证。
- **按规则可得性运行。** 结构化规则在通用模型覆盖范围内时本地仿真。依赖行内私有引擎或服务的规则用银行预发环境执行，再导入结果对照。规则仍在草案阶段时，按标注的假设试算。
- **用证据闭环。** 采用同一批代表案例核对门槛、重复通知、部分退款、预算耗尽及奖励变化。结果和差异供银行团队处理，正式版本调整后引入新快照复跑。

## 接入设计的检验

先用两种不同结构的模拟来源验证同一份软件能否靠更换接入配置复用同一批案例。接入一家银行的常规产物是一份接入配置和一套经该行确认的代表案例，有需要时加轻量只读连接器。真实可覆盖范围以可获取的规则快照和预发证据为准。
