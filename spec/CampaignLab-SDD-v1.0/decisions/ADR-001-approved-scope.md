# ADR-001 产品范围和技术栈

2026-11-12。状态 `OWNER_CONFIRMED_FOR_DESIGN`。批准证据为发起人在本会话明确回复「确认三项选型」，同时要求补齐各技术栈开发规范、对标与后续研究，以及可供本机 Codex 实施的离线交接包。

| 决定 | 依据 | 落地 |
|---|---|---|
| 上线前规则验证与上线后策略复盘共用案例与证据 | 原型复盘可定位异常，规则验证可追踪预发差异 | 案例保留来源问题、预期、规则、样本与实际。下期验证关联改进项 |
| 满额赠券、远程回拨为首版端到端流程 | 前者覆盖金额、叠加、预算、退款，后者覆盖跨行接入、漏斗、频控及复盘 | 样例、预期和验收同时交付，页面依赖实施顺序见开发计划 |
| Ubuntu 本地单机，Python 后台与分析，Vue 前端 | 单人维护、可本地回放，工作台需要高密度对照与可追溯交互 | CPython 3.14、uv、FastAPI、Pydantic v2、Uvicorn、SQLite、SQLAlchemy 2.x、Alembic、DuckDB、Parquet、Vue 3、TypeScript、Vite、Element Plus、ECharts |
| 文件接入为首版边界 | 已确认的跨行设计约定 | 导入 CSV、JSON。宽长表通过映射配置归一。正式平台提供快照和回执 |
| 开发框架使用一个应用与一个执行进程 | 导入、批量复跑和报告需持久任务与重试 | 本机短事务管理作业。独立分析连接读取不可变快照 |
| 逐页设计以 Markdown 交付 | 发起人要求交给本机 Codex 实施 | 页面、接口、状态、样例和验收逐项对应 |

原阶段 00 的购买价值验证继续列在后续研究中。运营岗位真实上手、独立复用、付费和真实银行授权对账，各有后续验证条件。55 个材料点位的证据口径沿用原型记录，实际应用以本包契约与实测验收为准。
