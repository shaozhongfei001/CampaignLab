# 开发角色、阶段和移交

## 角色和权限

| 角色 | 主责 | 提交给下一角色 |
|---|---|---|
| 项目负责人 | 确认产品范围、业务口径、权限和验收结论 | 选型与变更裁定 |
| 需求与产品 | 维护来源、使用者、场景、取数和业务验收 | 需求与页面依赖、异常和样例 |
| 技术负责人 | 拆任务、检查契约一致性、合并与运行 | 技术任务、版本、环境证据与分歧 |
| 前端设计 | 逐页交互、视觉令牌、异常、快捷操作 | 页面与公共组件契约 |
| 服务端开发 | 会话、API、状态、SQLite 和作业 | HTTP 证据、迁移和恢复 |
| 数据与规则开发 | 映射、DuckDB 指标、规则回放、差异和报告计算 | 黄金用例、对账、链路证据 |
| 前端开发 | 路由、视图、状态、表单、接口和导出 | 浏览器业务操作与回归 |
| 独立 QA | 从已交付提交和固定数据重跑，核查状态与业务预期 | 独立结果、缺陷、复测及范围声明 |

同一实现者可兼多个开发角色。独立 QA 读取实际产物和运行证据，并作为单列角色给出判断。项目负责人对实质业务变更和最终交付负责。

## 实施顺序

| 阶段 | 输入 | 实施任务 | 可交接条件 |
|---|---|---|---|
| M0 框架与本机入口 | 工具链、OpenAPI、DDL、工作区契约 | 建仓、锁版本、会话、路由壳、迁移、健康、校验与本机启动 | 目标环境安装；数据库首迁；会话、隔离、健康和浏览器入口通过；见 AC-001、031、034、035 |
| M1 数据接入与比较 | A/B、CSV 样本、数据与口径契约 | 读取宽长表，验证、发布、更正；字典、渠道、窗口、对账 | AC-005 至 011、020。相同软件接入两来源，差异明确且可追踪 |
| M2 规则与验收 | 规则模板、案例、预发向量、活动契约 | 规则确认、检查、单例与批量、冻结预期、预发与回执 | AC-002 至 004、012 至 017，赠券及回拨规则独立实测 |
| M3 复盘与诊断 | 指标、范围、阈值、60 条问法 | 参与度、漏斗、产能、诊断、试算、专题入口 | AC-018 至 024、033，结果与黄金样本一致 |
| M4 报告与闭环 | 已算复盘、验收候选和版本 | 报告、签认、修订、改进、复核、证据导出 | AC-025 至 028、030。历史签认和后续记录可同时查询 |
| M5 端到端与交付 | 已实现代码和锁文件 | Playwright 双流程、故障与恢复、离线运行、性能和独立 QA | 所有适用 AC 提交实际证据，范围、缺项、环境与责任清楚 |

M1、M2 在 M0 的对象、ID 和 API 契约齐备后可独立实现，M3 依赖 M1，M4 汇合 M2、M3。技术负责人持续收敛可恢复问题。真实银行数据依赖作为待补条目保留，用合成样本完成授权首版。新增业务含义须有裁定。文档改动对关联用例与接口检查负责。

## 阶段回执与验收判断

每阶段回执记录阶段、提交哈希、规范版本、环境、命令、退出码、样本摘要、输出路径和缺陷。缺陷用 BLOCKER、MAJOR、MINOR、NOTE，明确受影响对象、复现、实际和预期、负责人、复测。独立 QA 先确认提交、锁文件、范围和证据齐全，再按任务给出通过、带待办通过或退回。项目负责人在实际浏览器及数据证据齐备后确认交付。包内的设计核验、历史原型测试、开发自测及独立 QA 各自记录。
