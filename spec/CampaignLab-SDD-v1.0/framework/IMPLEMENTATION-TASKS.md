# 本机实施任务清单

在 [阶段和角色](DELIVERY.md) 下执行。技术负责人可按接口依赖分工，任务完成依据为运行证据。下表中的测试编号见 [验收](../qa/ACCEPTANCE.md)。

| 任务 | 负责角色 | 依赖 | 执行与出口 |
|---|---|---|---|
| M0-01 | 技术负责人 | 规格索引 | 生成并提交真实 uv 与 npm 锁，记录目标平台、Python/Node/SQLite/浏览器，完成依赖安装和版本诊断 |
| M0-02 | 服务端 | M0-01 | 建服务入口、会话、工作区、Problem、ETag 与幂等包装，首迁比对 DDL，验证 AC-001、034、035 |
| M0-03 | 前端 | M0-01、OpenAPI | 建路由、主题、表格和证据框架，生成类型客户端，完成 UI-01 和键盘基线 |
| M0-04 | 服务端 | M0-02 | 建持久作业、认领续租、取消重试和原子制品，验证 AC-029 的负例 |
| M1-01 | 数据与服务端 | M0-04 | 实现三格式文件与映射，A/B、CSV 和 JSON 走相同规范校验，完成 AC-005、006 |
| M1-02 | 数据与服务端 | M1-01 | 发布、更正、覆盖与定义读取，保留原版本，完成 AC-007、008、020 |
| M1-03 | 数据 | M1-02 | 实现同义对账、六渠道重算及窗口候选，完成 AC-009–011 |
| M1-04 | 前端 | M0-03、M1-01–03 | 实现 UI-06–11，逐个状态对照接口和数据 |
| M2-01 | 服务端与规则 | M0-02 | 活动、绑定、规则版本、条款和边界检查，AC-002–004 |
| M2-02 | 规则 | M2-01、M0-04 | 事件回放、金额分、状态与轨迹。15 条黄金案例的原版和候选结果均对齐，AC-012–015 |
| M2-03 | 服务端与规则 | M2-02 | 冻结候选、预发差异、审阅、回执与过期，AC-016、017 |
| M2-04 | 前端 | M0-03、M2-01–03 | 实现 UI-02–05、12–16，完成赠券闭环浏览器走查 |
| M3-01 | 数据 | M1-02 | 汇总、口径、分母、期间基准与分组，AC-018–020、033 |
| M3-02 | 数据 | M3-01 | 阈值、诊断、分解、趋势、试算，AC-021、022、024 |
| M3-03 | 数据与服务端 | M3-01、M3-02 | 登记问法、澄清、报告意图及计划执行，AC-023 |
| M3-04 | 前端 | M0-03、M3-01–03 | 实现 UI-17–20 和关联取数、源证据入口 |
| M4-01 | 服务端与数据 | M3-03 | 普通及专题报告、签认与修订，AC-025、026 |
| M4-02 | 服务端 | M2-03、M4-01 | 改进项、观察、审计和导出，AC-027、028、030 |
| M4-03 | 前端 | M0-03、M0-04、M4-01–02 | 实现 UI-21–26 与端到端回拨复盘走查 |
| M5-01 | 技术负责人 | M4-03 | 运行固定环境回归、离线验收、性能和备份恢复，记录环境与制品 |
| M5-02 | 独立 QA | M5-01 | 按交付提交和锁文件独立重跑全部适用 AC，提交通过或退回 |
| M5-03 | 项目负责人 | M5-02 | 依据实际结果确认交付范围和后续业务验证 |

任务拆分遵循逻辑依赖。接口、文件或状态变更与其消费者在同一变更集校验。设计缺项优先从权威来源核对并修正，未获证实的行内业务留在已定义的待补分支。
