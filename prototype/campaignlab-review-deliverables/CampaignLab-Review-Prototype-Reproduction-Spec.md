# CampaignLab｜营销策略复盘原型复现说明

2026-11-11 · v0.1 · 页面、流程、数据及重建约定

## 1. 交接目标

接手人从交接包直接打开原型，能完成一次从导入两期数据到下期复核的业务任务。需要重建时，从同一份源码生成字节一致的 HTML 和甲乙数据，并复跑全部断言。需求依据和逐项覆盖见同包的《CampaignLab-Review-Acceptance-Checklist.md》。银行原件仍由授权使用者管理，交接包使用合成数据。

| 读者／角色 | 在原型中的工作 |
|---|---|
| 分行运营、客群经理 | 选复盘范围，核对数字，找异常，形成报告与改进项 |
| 指标负责人 | 核对源批次、渠道定义、分母、采集覆盖和关联口径 |
| 渠道运营、策略负责人 | 下钻过程与产能，登记假设，比较原规则与候选规则 |
| 复核与验收人员 | 签认模拟报告，核对行内模拟预发，查看后续观察 |
| 迁移执行智能体 | 按本说明重跑流程，按源码和校验值复现交付，再实施经确认的变更 |

本原型的签认、预发与发布回执为模拟业务记录。正式策略变更、审批、发布和执行由银行营销活动管理平台负责。

## 2. 打开、构建和核验

**打开交付。** 在 Chrome 或 Edge 中直接打开 `campaignlab-review-deliverables/CampaignLab-Strategy-Review-Prototype.html`。HTML 内嵌 CSS、逻辑、两套初始数据和验收问法。首屏默认甲行、东岚分行、2026 年 10 月、远程渠道、上月环比。甲乙 JSON 可各自导入，导入会校验并从文件中读取接入配置。

| 包内文件 | 责任与变更位置 |
|---|---|
| `campaignlab-review-deliverables/CampaignLab-Strategy-Review-Prototype.html` | 可运行的交付件。内嵌数据与两个独立 JSON 具有相同结构和值 |
| `campaignlab-review-deliverables/CampaignLab-Simulated-Bank-A.json`、`CampaignLab-Simulated-Bank-B.json` | 可独立导入的宽表与长表样本 |
| `campaignlab-review-deliverables/CampaignLab-Review-Acceptance-Checklist.md` | 材料点位、条件、操作步骤和验收结果 |
| `campaignlab-review-deliverables/CampaignLab-Review-Prototype-Reproduction-Spec.md` | 本文，说明各页目的、组件顺序、业务规则和迁移约定 |
| `campaignlab-review-work/shell.html`、`style.css` | HTML 壳、导航和工作区容器、页面布局、视觉与响应式样式 |
| `campaignlab-review-work/core.js` | 导入归一、去重、范围与基准、计算、问法、回放和报告 |
| `campaignlab-review-work/ui.js` | 六页渲染、交互、事件处理、导出和本地记录 |
| `campaignlab-review-work/generate_data.py` | 两套数据与问法夹具的确定性生成 |
| `campaignlab-review-work/build.py`、`package.py` | 将源码装入单个 HTML，打包和生成校验清单 |
| `campaignlab-review-work/verify.mjs`、`verification-results.json` | 可重复执行的核验，以及本次计算核验逐项结果 |
| `SHA256SUMS` | 包内交付件和源文件校验值 |

从解压根目录执行。构建只用 Python 标准库，核验只用 Node.js 内置模块。本次环境为 Python 3.12.14、Node.js 24.22.1。文件编码 UTF-8，换行 LF。

```bash
python campaignlab-review-work/generate_data.py
python campaignlab-review-work/build.py
node campaignlab-review-work/verify.mjs
sha256sum -c SHA256SUMS
```

预期程序输出 `79/79 PASS`。构建产物写回 `campaignlab-review-deliverables/`，另外生成同字节的 `campaignlab-review-work/dist/index.html` 供本地静态预览。重打包运行 `python campaignlab-review-work/package.py`，输出 ZIP。构建步骤固定内容和顺序；操作界面的日期选择和本地记录由浏览器独立保存。不同平台的字体渲染以同源 CSS 为基准。

## 4. 六个页面的详细设计

### 4.1 策略复盘

**目的。** 让业务人员从同一份快照看部署、触达、产能及优先核查项。此页是主要入口，对应 CL02、CL09–CL19、CL29、CL31–CL32。

| 从上到下的区域 | 字段、逻辑及操作 |
|---|---|
| 页头与公共筛选 | 标题「策略复盘」。右侧「生成复盘报告」带入当前上下文至报告页，「下载当前明细」导出源切片和指标列 CSV。下方分行整体、总行下发、分行自主切换策略来源 |
| 四张经营卡 | 策略覆盖率、名单执行率、有效触达客户数、有效触达率。卡片显示本期、与可比基准的绝对差和相对差。点击看公式、分子分母、口径版本、批次、源行和范围 |
| 左栏五层漏斗 | 下发、下发成功、已执行、已接触、有效接触。条长相对下发人数，右侧显示较上一层转化。最低可算层用琥珀色。点一层打开相应指标证据 |
| 右栏优先核查 | 接触层间转化和基准，显示差值、影响最大的量率项和模拟渠道容量。按钮「打开异常诊断」进入有效触达的默认拆解 |
| 专题、参与度、执行效果 | 有客群选择时显示部署客群／月末标签、特色次数、有效接触及 AUM。有活动选择时显示有效期内绑定及特色指标。参与度列本次范围、全行和各组及三种月增／环比。执行效果列 AUM、存款、理财、基金、个贷和各产品销量及策略来源拆分 |
| 过程与产能明细 | 分行、渠道、支行三个标签实际切换分组。列下发、执行、接触人数和各自比率及金额。表宽超过视口时由容器滚动 |

**首屏验收值。** 两期五层分别为 10,000／9,600／7,680／3,840／1,920 与 12,000／11,520／8,640／3,456／1,728。当前覆盖率 73.14%、名单执行率 75%、有效触达率 15%。接触层间转化由 50% 降到 40%，最后一层相对上一步仍是 50%。可复算为 1,728÷11,520 与 1,728÷3,456。

### 4.2 数据与口径

**目的。** 检查导入、字段映射、两行口径和关联明细。对应 CL01、CL03、CL20–CL30。

| 区域 | 字段、状态及操作 |
|---|---|
| 页头 | 「导入数据文件」打开 JSON 选择器。「对比甲乙行」使用同一筛选核对五层、有效触达率、AUM。定义一致且数值相等显示已对齐；不同定义或范围待核 |
| 数据快照／来源映射 | 左侧银行、快照、接入配置、源表、切片数、来源和导入记录，下方下载两份样本。右侧列对象、源字段或指标码、单位转换。甲宽表取列，乙先按切片和指标码组装再统一金额 |
| 口径和覆盖 | 经营率、层间率分母，去重依据，客群口径、采集记录与本次不可比原因。「查看分母与原行」打开有效触达率证据 |
| 各渠道漏斗口径 | 五层 × 六渠道矩阵。短信与推送用点击及详情，企微用交互／时长／点击，AI 外呼有频控，远程区分条线时长，客户经理使用下游已核判定 |
| 历史事件口径重算 | 选择渠道、条线、时长、轮次，勾选收到、拨打、接通、送达、消息、点击、详情、频控、时段、下游有效。提交后展示五层各自命中 |
| 下发、触达和产能关联 | 展示当前窗口版本、两个日期差、候选触达、金额、命中状态和采用策略。多候选默认待核，「采用最近触达」选择日期差最小的唯一候选，平局仍待核。「恢复待核」撤回该演示选择 |

**关键验收。** 同口径远程的两行结果完全一致。切手机银行推送时，乙行使用额外详情停留 3 秒条件，界面提示口径差异。远程财私 59 秒未命中、60 秒命中，个贷边界 9／10 秒。O-01 有 T-01、T-02 两候选，模拟采用最近触达时为 T-02。

### 4.3 异常诊断

**目的。** 用自然问法查数、定位变化并形成有证据的改进动作。对应 CL04–CL05、CL34–CL45。

| 区域 | 字段、状态及操作 |
|---|---|
| 问答 | 问法类别、R01–R56／Q01–Q04 样例、业务问题输入和查询。解析器识别登记的时间、机构、渠道、指标、筛选、方向、报告类型。结果首行展示识别的范围和版本 |
| 问答输出 | 数值给本期、基准、可比差值；口径给算式和来源；异常给规则与影响；归因给下钻；组合按要求先查数再归因；报告给「按该范围生成报告」；歧义给澄清提示。题述数值显示为待核输入，计算采用导入值 |
| 异常清单与阈值 | 五类阈值初始 T-1。选择单一规则或全部，填阈值并应用生成 T-2 等会话版本，保留前版阈值。列表列指标、对象、判定、值、变化、基准、影响 |
| 贡献拆解 | 指标选择及漏斗、渠道、客群、支行、策略来源、分行、存款类型选择。默认主例给五项量率拆解和净变化。维度表列基准、本期、贡献和去重／未分配余量 |
| 趋势与行动 | 六月趋势按当前范围显示。五类待核假设分别附动作和责任岗位。点击「生成改进项」填写假设、动作、责任、验证证据、30／90 天和日期，保存进入报告与改进。「进入试算」带当前范围继续验证 |

**关键验收。** 默认净变化 −192 人。按下发量、成功率、执行率、接触率、有效接触层间率的固定顺序，贡献 +384、0、−144、−432、0。R08 过滤出两分行，Q03 请求用户明确触达指标，R54 带入客户经理专题报告。

### 4.4 试算与回放

**目的。** 让运营人员试算量级、核对原规则并生成复跑案例。对应 CL51–CL52。

| 区域 | 字段、状态及操作 |
|---|---|
| 情景估算 | 以已执行数和最后一层转化率为固定输入。可输入 0–100% 的接触层间转化假设，显示当前有效接触、试算值和差值。默认 45%，由 8,640×45%×50% 得 1,944。缺汇总或分母时显示待算 |
| 原规则与改案双栏 | 按本期、分行、渠道、活动筛出历史事件。顶部样本、日期、脱敏合成编号、原版本、实际来源、已用次数和上限。左 V1 到达先后，右候选 V2 预约优先。两列逐步显示命中、抑制和赢家 |
| 三个样本 | SIM-017 原规则实际与复算均为 S-201，改案 S-101；SIM-018 原规则结果与实际有差异，保存按钮不可用；SIM-019 频次已耗尽，两种规则均无分配 |
| 仅汇总、保存与移交 | 「模拟仅有汇总」让逐笔回放进入缺证据状态，保留情景估算。原规则一致且活动已绑定时可保存案例，关联本期改进项。验证记录列案例、快照、活动和期望。活动工作台接收同一案例 |

### 4.5 报告与改进

**目的。** 审阅可追溯的报告并跟踪动作、签认、更正和下期。对应 CL46–CL50、CL53。

| 区域 | 字段、状态及操作 |
|---|---|
| 页头与报告状态 | 标题及当前范围、快照、比较基准。待核结论可提交签认，部分可比草稿标明范围，缺本期或基准时展示取数清单。可导出报告或取数清单 Markdown |
| 报告正文 | 七段顺序为执行摘要、分行参与度、执行漏斗、执行效果、异常归因、行动建议、附录。摘要三条和异常表。专题追加指定范围指标对照。附录有批次、截止、定义和源行键 |
| 改进记录 | 每项含编号、假设与动作、负责人、时间、证据、状态。查看、分派、保存为待验证。下期复核沿该项原范围比较下一月，用户记录已复核、方案未通过或证据不足 |
| 签认与历史 | 填写模拟签认人，保存当时的范围、阈值、快照、正文和证据。点击「查看原报告」读取保存版本。模拟迟到数据产生 A-001-R1 等更正，相关动作待复核，已签认报告仍可导出 |

**关键验收。** 原甲行快照的默认 AUM 为 −4,074,000 元。补数 +125,000 元后新值为 −3,949,000 元。旧报告保留原数字。选 2026-01 环比时因 2025-12 基准缺失只生成取数清单。

### 4.6 活动工作台

**目的。** 将复盘发现转成上线前验收记录，并登记行内证据。对应 CL07、CL32、CL52。

| 区域 | 字段、状态及操作 |
|---|---|
| 活动与策略版本 | 选择活动。显示编号、相关策略、版本、关系生效期、来源证据和发布回执。绑定有效时可跳到关联复盘；待绑定活动列缺项 |
| 复盘案例列表 | 每行案例、原结果、候选规则、期望、预发观察和结论。导入 PRE-101 后以实际观察逐条比期望，显示通过或待核差异 |
| 发布回执与下期 | 已保存案例且全部预发一致时允许登记模拟 V2 发布回执 REL-101。关联改进项改为待复核。「查看下期复盘」以案例分行、渠道和下一统计月回到首页 |

**关键验收。** SIM-017 的候选结果为 S-101，模拟预发一致。登记回执后切到 2026-11 与 2026-10 比较，有效触达 1,944、变化 +216 人，界面口径为模拟观测。

## 5. 端到端流程和分支

| 流程 | 发起条件与输入 | 操作顺序与状态变化 | 输出及验收 |
|---|---|---|---|
| F1 导入及对齐 | 指标负责人取得一份格式版本 1 的合成 JSON | 顶栏导入 → 校验表列、字典、切片、阶段、金额 → 相同版本且内容一致时复用，内容冲突时提示改版本 → 映射为统一统计切片 → 打开数据与口径 | 当前行、批次、字段映射、记录数。远程同语义对齐，推送定义差异待核。校验失败保留当前数据。对应 UI03、V01、V13、V17 |

### 6.2 精确计算和可比性

| 业务概念 | 算法与边界 |
|---|---|
| 人数去重 | 以 period、cohort 为组，将每条切片在某阶段表达为左闭右开的 [offset, offset+人数) 合成客户区间，计算区间并集。组间相加，跨月为客户月次。真实银行须提供权威去重汇总或授权明细 |
| 部署和覆盖 | 已部署分行为有下发的分行去重数。策略数按统计月与策略编号去重。覆盖率=成功下发人数÷可经营客户 |
| 过程比率 | 下发成功率=成功÷下发；名单执行率=执行÷成功；经营触达率=接触÷成功；经营有效触达率=有效接触÷成功。漏斗接触层间=接触÷执行，最后层间=有效接触÷接触 |
| 产能和销量 | 归属后的余额增量和销量以元展示。金额按源单位转成元。余额可负；字段缺值则相应总量待核。存款增量可按活期和定期拆解 |
| 基准比较 | 先找期间、渠道、口径版本和相同截止进度的交集。分行同组均值等权并剔除本行，全行均值按分行等权。率的绝对变化用百分点，相对变化用百分比。正基数方算相对变化 |
| 五种异常 | 默认期间相对变化 ≥10%、同组下偏 ≥20%、低于自身前六可比月均值 ≥1 个总体标准差、层间相对同组下偏 ≥15%、渠道／客群／支行计次构成变动 ≥5 个百分点。变化方向由问题或判定规则确定 |
| 量率拆解 | 有效接触=下发×四个层间转化率。固定业务顺序逐项用本期替换基准，差额求和等于净变化。可比范围或分母缺失时提示证据缺口 |
| 维度拆解 | 人数或金额用维度差额，率按分组分子除以当期总体分母的份额比较。与总体之间的差异列入去重／未分配余量 |
| 关联窗口 | 合成客户键一致。远程下发日减触达日允许 0 或 10 天，产能日减触达日为 0–7 天含端点。推送分别为 0 天与 30–60 天含端点。方向、端点和最近触达优先为模拟约定 |
| 规则回放 | 固定单日同渠道触达上限及已用次数。V1 按到达时间，候选 V2 把已预约置前，再按时间、策略 ID 稳定排序。每个被抑制的候选保留理由。原规则差异待核 |
